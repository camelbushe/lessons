# Хэш таблицы
Структура данных, которая хранит элементы в виде пар ключ-значение.
## Что такое хэш функция
**Хэш функция** - это функция, которая принимает строку и возвращает число, которое будет соответствовать этой строке.
### Требования
- Для одной и той же строки всегда возвращает одно и тоже число.
- Одно и тоже число не может соответствовать ещё каким либо строкам.
## Суть
Хэш таблиц не существует в компьютерах. Это что-то абстрактное, но вот как она реализуется.
#### При добавлении
1. Принимаем строку
2. Пропускаем через хэш функцию
3. Сохраняем в массиве значение для соответствующей строки под индексом, который вернула функция.
#### При возврате
1. Принимаем строку
2. Пропускаем через хэш функцию
3. Обращаемся к массиву по индексу который вернула функция и получаем значение для переданной строки.
## Хэш таблицы в языках программирования
- В JavsScript это объекты
- В Python это словари


# Применение хэш таблиц
- Кэширования. Храним под ключами значения и если они существуют в таблице, то получаем из нее
```python
cache = {}

def getPage(url):
    if url in cache:
        return cache[url]
    else:
        page = generatePage(url)
        cache[url] = page
        return page
```
Сдесь мы получаем страницу по url. Если мы уже переходили по этому url, то страница уже сгенерирована и нам не нужно ее генерировать (что занимает много времени).
- Устранение дубликатов
```python
voted = {}

def check_vote(name):
    if name in votes:
        print("Не допускать")
    else:
        voted[name] = True
        print("Допустить")
```
Допустим мы проводим голосование. Голосовать нужно 1 раз. Если голос уже есть, то повторно голосовать не нужно
- Моделирование отношений между объектами
```python
phone_book = {}

phone_book["Bob"] = "235467"
phone_book["Mark"] = "729639"
```
Храним номера по имени пользователя


# Коллизии в хэш таблицах
Реализовать такую хэш функцию, которая будет выдавать уникальное число на каждый элемент **при условии, что размер массива не бесконечный** (т.е. память ограничена, а комбинаций ключей очень очень много) пратичеси не возможно. Поэтому могут возникать коллизии. Рассмотрим пример. У нас есть хэш таблица, а данные в массив указываются **в зависимости от первой буквы ключа**.
```text
[Тут буква а][Тут буква б][][][][]...[Тут буква я]
```
Если ключ апельсин, то значение для него помещается в первую ячейкку. Для яблока в последнюю. Но что если мы ещё добавим авокадо. Вознинет колизия. Чтобы это решить, в ячейку с оллизией помещают связанный список.
```text
[Коллизия] -> [Апельсин][0.63] -> [Авакадо][0.56]
[0.78 (цена банана)]
[]
...
```
Каждый узел связанного списка на месте коллизии хранит люч, значение и ссылку на следущий элемент.
## Коэффициент заполнения
Вычисляется по следущей формуле
```math
Load Factor = \frac{m}{n}
```
Где:
* $m$ - количество элементов в хэш таблице
* $n$ - общее количество элементов
```text
[][1][][0][]

LoadFactor = 0.4
```
По мере роста хэш таблицы приходится изменять ее размер. Это желательно делать когда кофициент заполнения достигает 0.7. Обычно в этом случае создаётся массив в двое больше предыдущего и в него переносятся элементы при помощи хэш функции.
```text
[4][1][3][] - Приблежается к заполнению
[][][][][][][][] - Создаём массив в двое больше
[][4][][1][3][][][] - Переносим элементы при помощи хэш функции
```
## Хорошая хэш функция
Хорошая хэш функция должна равномерно распределять элементы в массиве. Избегать коллизий. Есть хорошая функция под названием CityHash.


# Граф
**Граф** - модель, которая показывает набор связей.
Например нужно показать подписчиков. Тут показано, что Даник подписан на Лёшу.
```text
[Даник] -> [Лёша]
```
Граф состоит из узлов и рёбер. Узел может быть напрямую соединен с несколькими узлами.
```text
[Узел 1] - [Узел 2]
   |
    - - - - [Узел 3] 
```
Граф может быть направленным (ориентированным) и не направленным (неориентированным)
- Ориентированный имеет связь только в одну сторону. Например Даник подписан на Лёшу, но Лёша не обязательно подписан на Даника.
```text
[Даник] -> [Лёша]
```
- Неориентированный имеет двустороннюю связь. Например Даник и Лёша друзья в социальной сети.
```text
[Даник] - [Лёша]
```
# Очередь
Эта структура данных работает по принципу первый зашёл, первый вышел. Поддерживается только добавление в конец очереди и получение элемента из начала очереди.
```text
[1][2][3] +[4] добавляем в конец 4
-[1] [2][3][4] убираем из начала 1.
```


# Поиск в ширину
Помогает ответить на два вопроса:
- Существует ли путь от узла А к узлу Б
- Как выглядит кратчайший путь от узла А к узлу Б

Предположим у нас есть подписки в социальных сетях. И нам нужно найти среди них продавца манго. Для упрощения будем использовать направленный граф и тем самым предположим, что твои подписки не могут быть вашими подписчиками.
Все эти подписки являются направленным графом. 
## Уровни
У нашего графа есть несколько уровней:
1. Мои подписки
2. Подписки моих подписок
3. И так далее
## Как работает алгоритм
Мы берём все мои подписки и добавляем в очередь. Затем проверяем первого человека из очереди. Если он не является продавцом, то добавляем его подписки в конец очереди. Затем тоже самое со вторым и так далее пока не найдем продавца. Это позволит обеспечить то, что связи первого уровня имеют больший приоритет.
### Важные замечания
Важно исключать дубликаты. Если человек уже есть в очереди, то его не нужно добавлять снова так как это может вызвать зацикленость.
## Итого алгоритма
Таким образом если существует путь из узла А в узел Б, то поиск в ширину находит кратчайший путь. Если путь не найден, то пути не существует
## Время выполнения
Чтобы найти продавца нужно в худшем случае пройти по всем рёбрам. Время выполнения составляет O(количество рёбер)

Помимо этого нужно выполнять добавление в очередь. Добавление происходит за O(1), но количество добавлений зависит от количества людей. В итоге суммарное время добавления составляет O(количество людей).

Все время выполнения составляет O(V+E), где V - количество вершин (людей), а E - количество рёбер
## Реализация графа в JavaScript
Граф это будет свзяннный список. Ключ - имя подписки. Значение - список его подписок:
```javascript
const graph = {
 "Даник": ["Дима", "Лёша", "Сева"],
 "Лёша": ["Петя", "Дима"]
}
```


# Деревья
В данном руководстве будет вестись работа с корневыми деревьями, поэтому далее слово дерево подразумевает корневое дерево. Дерево представляет собой связанный ациклический граф. У дерева есть корень - узел без родителей из которого можно перейти в любой другой узел. Листья дерева - узлы без дочерних элементов. Все узлы, кроме корневого, имеют как минимум одного родителя.
```text
            [Корень]
             /     \
           []       [Лист]
          /
     [Лист]
```
Например, каталоги файлов являются хорошим примером деревьев.
## Поиск в ширину
Так как дерево является графом, то к нему можно применять поиск в ширину.
## Поиск в глубину
Данный алгоритм также позволяет пройтись по каждому узлу дерева, но в отличие от поиска в ширину не позволяет находить кратчайший путь.
Пример реализации на JavaScript:
```javascript
// Выводит имена файлов из указанной директории и из других дочерних директорий
function printNames(dir) {
 // Проходим по каждому элементу из директории
 for (const element in getDirectoryElements(dir)) {
  // Получаем полный путь текущего файла
  const fullPath = joinPath(dir, element.name)
  if (element.isDirectory) {
   // Продолжаем рекурсивный обход если элемент в директории является другой директорией
   printNames(fullPath)
  } else {
    console.log(element.name)
  }
 }
}
```
## Бинарные деревья
Бинарное дерево - это разновидность дерева, которое имеет **не более** двух дочерних узлов. Примером такого дерева может служить генеалогическое дерево.
```text
            [Корень]
             /     \
      [Узел 1]     [Узел 2]
```
Узел может один, главное чтобы их было не больше двух
```text
            [Корень]
             /     
      [Узел 1]
```
### Наименования
Узлы в таком деревне могут назвать как левый или правый узел. Есть также левое и правое поддерево.
```text
             [Корень]
             /      \
      [Узел 1]       [Узел 2]
       /  \
[Узел 3] [Узел 4]
```
Узел 1, 3 и 4 относятся к левому поддереву.


# Код Хаффмана
Данный алгоритм позволяет сжимать текст
## Как работает алгоритм
- У нас есть исходный текст. Предположим это слово TILT.
- Мы подсчитываем сколько раз в тексте встречается каждая буква. T: 2, I: 1, L: 1.
- Далее строится бинарное дерево. Все буквы располагаются в его листьях. Чем реже буква встречается, тем дальше она от корня это позволяет ещё сильнее уменьшить размер файла:
```text
    []
   /  \
  []   [T]
 /  \
[I] [L]
```
- Затем текст представляется в двоичном виде. Чтобы узнать кодировку символа, мы должны идти к листу с символом от корня. Если мы поворачиваем на лево, то добавляем 0, если на права, то 1. Корень не учитывается. Например буква L будет иметь кодировку 01, буква T 1. Таким образом слово TILT можно закодировать в виде 1 00 01 1.
## Декодирование текста
Мы пробегаемся по битам, которые представляют сжатый текст:
- Первый бит 1. Значит мы должны повернуть на право. Проверяем, является ли узел, к которому мы пришли листом дерева, если да, то печатаем букву, которая там лежит, если нет, то возвращаемся к корню и проверяем следующий бит.
- Следующий бит является 0. Мы находимся снова в корне. Поворачиваем на лево. Проверяем, чем является узел. Так как узел не является листом, проверяем следующий бит. Он равен нулю. Снова поворациваем на лево (не возвращаясь к корню). Данный узел евляется листом. Печатаем букву, которая там лежит. Возвращаемся в корень и проверяем следующий бит.
- И так далее...

Стоит обратить внимание, что для этого бинарное дерево должно храниться в файле.
Изза того, что дерево бинарное и буквы храняться в листьях это гарантирует, что к каждому символу есть только один путь и соответственно каждой букве будет соответствовать только одно двоичное представление


# Сбалансированное дерево (BST)
Это разновидность бинарного дерева у которого значение левого дочернего узла меньше самого узла, а значение правого узла больше самого узла. А также все числа в поддереве левого узла всегда мньше самого узла. Это позволяет выполнять поиск по очень быстро
```text
    [20]
    /   \
  [10] [30] 
  /  \
[5] [15]
```
## Короткие деревья работают быстрее
Лучший случай
```text
       [20]
       /   \
   [10]     [30]
  /    \    /   \
[5]  [15] [25]  [35]
```
Худший случай
```text
[20]
    \
    [25]
        \
        [30]
            \
            [35]
                \
                [40]
                    \
                    [45]
                        \
                        [50]
```
Оба дерева имеют 7 узлов, но высота первого равна 2, а высота второго равна 6. У первого дерева поиск будет выролняться за O(logn), а у второго за O(n).
