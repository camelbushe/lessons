# Как работает сборка/компиляция
**Внимание** - у меня реализация == определению.
- .h файлы содержат только **объявления**. Их нужно включать туда, где используется указанная в нём функция. Несколько одинаковых **объявлений** не вызовут конфликт.
- Для того чтобы найти реализацию для данной функции нужно указать .cpp файл в котором она содержится.
- Имена .h и .cpp не обязательно должны совпадать.
- На один проект должно быть только одно определение данной функции/идентификатора (Правило одного определения).
- Включать стоит только .h файлы. Так как если в нескольких файлах нужно вызвать функцию, то .cpp приведут к тому, что будет несколько реализаций данной функции, что приведет к ошибке.
- Препроцессор просто вставляет содержимое подключенных файлов прямо в код.


# Приоритет операторов и ассоциативность
Использовать скобки для лучшей читабельности.
```c++
x && y || z;
```
Хоть && имеет приоритет над || лучше заключать в скобки
```c++
(x && y) || z;
```
Заключать в скобки все кроме умножения, деления, сложения, вычитания. Или
```c++
x = (y *= z);
```
В специффикации нет указания в каком порядке вычислять операнды и аргументы функций. Например
```c++
a + b;
```
Нет разницы что первее вычислить a или b. Тоже самое с аргументами функций. Иззаэтого разные компиляторы могут вычислять как справа на лево так и наоборот. Изза этого могут быть разные результаты в зависимости от компилятора.
```c++
#include <iostream>

int getValue() {
  int x{};
  std::cin >> x;
  return x;
}

int sum(int x, int y, int z) {
  return x + (y * z);
}

int main() {
  std::cout << sum(getValue(), getValue(), getValue());
  return 0;
}

```
Изза этого лучше каждое getValue() записать в отдельные переменные а затем их передать в функцию.

(В с++ термин вычисление обычно применяется к вычислению операндов а не всего выражения целиком.)!


# Арифметические операторы
унарный (не бинарный) operator- возвращает результат умноженнный на -1. Аналогично с operator+ но он возвращает это же число.
operator% находит остаток от деления.
operator/ имеет как целочисленное деление так и нет. Если Один или оба операнда это числа с плавающей точкой то результат будет такимже. Если оба целые, то и результат целый.
```c++
2.0 / 4; // Дробное число
2 / 4; // Целое число. (0 в данном случае т.к. целая часть только возвращается)
```
Можно использовать static_cast<> для того чтобы не терять дробную часть при делении целых чисел
```c++
constexpr int x{7};
constexpr int y{2};

std::cout << static_cast<double>(x) / y; // 3.5
```
Деление на 0 приведет к неопределённому поведению. Деление на 0.0 определяется реализацией (компилятором/архитектурой)
|Оператор|Аналог|
|---|---|
|x += y|x = x + y|
|x -= y|x = x - y|
|x *= y|x = x * y|
|x /= y|x = x / y|
|x %= y|x = x % y|
**Модифицирующие операторы** - Возвращают значение и модифицируют один из операндов (=, +=, ...)
**Не модифицирующие операторы** - Только возвращают значение
Операторы можно перегружать и можно сделать чтобы их поведение отличалось от встроенных

# Операторы инкремента и декркмента. Побочные эффекты
Есть постфиксные и префиксные операторы инкримента и дикримента.
|Версия|Описание|Пример|
|---|---|---|
|Префиксная|Увеличивает/уменьшает значение на 1 и ВОЗВРАЩАЕТ УВЕЛИЧИННОЕ|++x|
|Постфиксная|Увеличивает/уменьшает значение на 1 и ВОЗВРАЩАЕТ ИСХОДНОЕ|x++|
#### Как работает постфиксная
Создается временная копия x с исходным значением. Оригинал увеличивается/уменьшается затем возвращается копия, потом копия удаляется. Эта операция занимает **больше ресурсов**
### Побочные эффекты
Выражение считается имеющим побочный эффект если они делают еще чтото наблюдаемое кроме возвращаения значения. Например x = 5. Тут возвращается 5 но ещё и присваивается значение.

Побочные эффекты + не определенный стандартом порядок вычисления операндов или аргументов функции может привести к разным результатам в зависимости от компилятора
```c++
x + ++x;
```


# Оператор запятая
```c++
(++x, ++y);
```
Сначало выполнится увеличение x, затем увеличение y и вернется увеличенное значение y. Тоесть этот оператор вычисляет сначало левый операнд, затем правый и вернёт правый.
Этот оператор имеет самый низкий приоритет:
```c++
z = a, b;
```
Z получит значение a. b вычислится и отбрасывается.
Изза этого этот оператор лучше вообще не использовать за исключением цикла for.
Не стоит путать этот оператор с разделителем. Напрмер запятая это разделитель аргументов функций.
Не стоит использовать в качестве разделителя только при объявлении нескольких переменнх (т.е. вообще не объявлять так переменные)
```c++
constexpr int x{ 5 }, z{ 6 };
```


# Условный оператор
```text
условие ? выражение1 : выражение2
```
Если условие возвращает true, выполняется выражение1, иначе выражение2.
Этот оператор можно использовать в константных выражениях так как он является выражением в отличии от if...else.
```c++
constexpr bool isTrue{ false };
constexpr int x{ isTrue ? 1 : 0 };
std::cout << x << std::endl;
```
Типы второго и третьего операнда должны либо **совпадать** либо конвертироваться в **одинаковые типы**
```c++
std::cout << (true ? 1 : 2); // Это нориально
std::cout << (true ? 1 ? 2.2); // Это тоже нориально так как 1 можно конвертировать в дробное число
std::cout << (true ? -1 : 2u); // Это тоже сработает, но -1 конвертируется в unsigned int изза этого получается очень большое число. Так не стоит делать
```


# Операторы сравнения. Сравнение чисел с плавающей запятой
Условие в блоке if ожидает булево значение (если не булево, то оно конвертируется). Сравнивать это значение с true или false считается избыточным.
### Больше, меньше с плавающей запятой
Изза ошибок округления (100.0 - 99.9 != 0.1) сравнивать числа с плавающей запятой считается небезопасным, но это может быть приемлимо если в програме не важна такая точность.
### Равно, не равно с плавающей запятой
Использование считается опасным. Когда можно сравнивать
- Сравниваются литералы (**без математических операций**) и число знаков после запятой не привышает максимум для этого типа. Литералы имеют **один и тот же тип**.
```c++
someValue() == 0.1; // Нормально. При условии, что someValue возвращает литерал.
0.7 == 0.7; // Норально.
0.1 + 0.2 == 0.3; // Не нориально. Есть математические операции.
0.9f == 0.9; // Не нормально. Разные типы.
```
### Как можно сравнивать
Можно написать несколько функций
- Использование абсолютной погрешности
```c++
#include <cmath> // Для std::abs

bool absIsEqual(double a, double b, double epsilon) {
    return std::abs(a - b) <= epsilon;
}
```
Сдесь a и b числа, а epsilon это абсолютная погрешность. После какой разничы числа считать идентичными. Минус - нужно выбирать погрешность в зависимости от входных данных.
- Использование относительной погрешности. Это позволяет указывать погрешность в процентах относительно большего числа.
```c++
#include <algorithm> // Для std::max
#include <cmath> // Для std::abs

bool relIsEqual(double a, double b, double epsilon) {
    return std::abs(a - b) <= (std::max(std::abs(a), std::abs(b)) * epsilon);
}
```
Тут погрешность это процент от большего числа. 0.01 = 1%. В этом подходе есть минус - он плохо работает с малыми числами. Например a - 1.0 = 1.11e-16 изза ошибок округления в компьютере. Это максимальное число. Затем возьмём погрешнсть 1e-8. Изза этого будет проходить сравнение 1.11e-16 <= 1.11e-16 * 1e-8. Это вернёт false хотя математически a - 1.0 = 0.
- Использовать комбинированный подход. Мы будем использовать относительную погрешность, но на всякий случай передадим ещё и абсолютную. Важно учесть, что абсолютная погрешность не должна быть меньше чем порог, когда компьтер совершает погрешности при вычислении.

```c++
bool combinedIsEqual(double a, double b, double absEpsilon, double relEpsilon) {
    if (std::abs(a - b) <= absEpsilon) {
        return true;
    } // Если абсолютная погрешность очень маленькая, то это пройдет для маленьких, но не для больших чисел
    return relIsEqual(a, b, relEpsilon);
}
```
### Создание constexpr функций
Эти функции можно сделать constexpr начиная с C++23
```c++
constexpr bool relIsEqual(...) {...};
constexpr bool combinedIsEqual(...) {...};
```
До C++23 функция std::abs не была constexpr поэтому нужно писать свою, чтобы можно было сделать


# Логические операторы.
Operator! имеет довольно высокий приоритет.
### Порядок вычисления операндов
Операторы operator|| и operator&& имеют чёткий порядок вычисления операндов (с лева на право) в отличии от многих других, что является исключением. Например если левый операнд operator&& вернет false, то правый операнд вообще не будет вычислятся.
```c++
(x == 1 && ++y == 2); // ++y не выполнится
```
Но это не работает с перегруженными операторами. Они не будут так себя вести.
### Законы де Моргана
```c++
!(x && y) == (!x || !y);
!(x || y) == (!x && !y);
```
### Логический оператор XOR
Это так называемое строгое ИЛИ. Возвращает true только если оба операнда разные но false даже если оба true. Этот оператор отсутствует в языке. Но operator!= по факту выполняет ту же функцию.
```c++
!!a != !!b != !!c; // Так можно работать если a, b, c не булевы
```
### Альтернативное обозначение
Данные операторы можно записать как or and not, но предпочтительнее использовать символы вместо текста.

# Пространства имён
Позволяют избегать появления одинаковых имёе идентификаторов так как каждый новый идентификатор можно помещать в собственное пространство имён.
Название желательно писать с большой буквы, но можно и с маленькой. Пространство имён может быть объявлено только в глобальной оьласти видимости или внутри другого пространства имён.
```c++
namespace Plus {
    int doSomething(int a, int b) {
        return a - b;
    }
} // Объявление пространства имён

Plus::doSomething(1, 2); // Вызов функции из пространства имён

::doSomething(1, 1); // Валидная запись, но это ищет doSomething в глобальной области видимости. Это тоже самое если написать doSomething без оператора разрешения области видимости.
```
Использовать ператор разрешения области видимости без указания имени пространства имён полезно чтобы если функция вызывается внутри пространства имён, компилятор **сразу использовал глобальное пространство имён**, а не искал поднимаясь вверх.
```c++
void print() {
    std::cout << "Hello";
}

namespace Foo {
    void print() {
        std::cout << "Hi";
    }
    void greet() {
        ::print(); // Из глобального пространства имён
        print(); // Из текущего пространства имён
    }
}
```
### Предварительные определения
Нужно также писать в прострпнствах имён по такойже структуре.
```c++
namespace Plus {
    int doSomething(int a, int b);
}
```
Если будет несколько объявлений одного и того же пространства имён как в нескольких файлах так и в одном, то это не приведёт к ошибке. Они просто объединятся.
```c++
namespace Greet {
    void sayHi() {
        std::cout << "Hi";
    }
}

namespace Greet {
    void sayHello() {
        std::cout << "Hello";
    }
}
```
Не стоит расширять таким образом пространство имён std.
### Вложенные пространства имён
```c++
namespace Foo::Bar {
    void sayHi() {
        std::cout << "Hi";
    }
} // Это эвивалентно примеру ниже

namespace Foo {
    namespace Bar {
        void sayHi() {
            std::cout << "Hi";
        }
    }
}

Foo::Bar::sayHi(); // Вызов из вложенного пространства имён
```
Так тоже приемлимо
```c++
namespace Foo::Bar {
    void sayHi() {
        std::cout << "Hi";
    }
}

namespace Foo {
    void sayHello() {
        std::cout << "Hello";
    }
} // Добавляет только в Foo
```
### Псевдонимы пространства имён
Можно добавить псевдоним для пространства имён и к пространству можно будет обращаться как через псевдоним так и через изначальное имя
```c++
namespace Greet = Foo::Bar;
```
Следует избегать вложенности в пространствах имён более 3 уровней


# Локальные переменные
Локальные переменные имеют блочную область видимости. Нельзя получить доступ из родителя, но можно из дочерних. Они создаются в момент определения и уничтожаются в конце блока в котором они определены. 

Если в родителе есть переменная с именем как в текущем блоке, то будет использоваться из текущего блока (Скрытие имени, затенение). Но если перекрывается глобальная переменная, то к ней можно получить доступ через operator::. Следует избегать переопределения глобальных и локальных переменных.

Не стоит создавать блоки, единственная цель которых - ограничение области видимости. Переменную не стоит размещать во внешнем блоке если она нужна только в текущем.

# Введение в глобальные переменные
Объявляются вне любых функций (После директивы include) или в пространстве имён (предпочтитеьнее). Они видны в любом месте програмы. Имеют статическую/длительность, тоесть создаются при запуске програмы до началы выполнения main и уничтожаются при ее завершении.

Стоит добавлять префикс g или g_ если глобальные переменные одъявлены в **глобальном** пространстве имён.

Глобальные переменные по умолчани инициализируются нулём
```c++
#include <iostream>

int a; // Содержит 0

int main() {
    int b; // Не содержит 0
    return 0;
}
```
Но const и constexpr все равно должны иметь инициализатор даже если они глобальные.
```c++
#include <iostream>

const int a; // Ошибка
const int b{}; // Нориально ({} инициализирует нулём)
constexpr int c = 0; // Нормально
```
Использование неконстантных глобальных переменных следует избегать. 


# Внутренняя свезь
В языке есть 2 типа связи: внутреняя и внешняя.
- **Внешняя** - можно получить доступ из разных файлов (единиц трансляции). Например я объявляю глобальную переменную a в разных файлах. Это приведёт к ошибке изза повторного определения.
```c++
// my_lib.cpp
int a{ 10 };
```
```c++
// main.cpp
#include <iostream>

int a{ 10 };

int main() {
    std::cout << "Hello world!";
}
```
- **Внутреняя связь* - это значит, что переменная видна только в текущем файле (единице трансляции) и повторное определение точно такой же переменной в другом файле не приведёт к ошибке.

Как указать внутреннюю связь.
- Её по умолчанию имеют const и constexpr переменные.
- С помощью ключевого слова static
```c++
static int a{ 10 }; // Видна только в указанном файле
```
### Когда это использовать
- Идентификатор не предназначен для использования в других файлах
- Запрещено использовать идентификатор в других файлах (**Рекомендует руководство**)
### Почему const и constexpr по умолчанию имеют внутреннюю связь.
- Константные переменные нужны просто для инициализации какихто занчений. Они подключаются через заголовки в разные файлы только для того чтобы не прописывать каждый раз их определение.
- Обычные переменные подключаются через заголовочные файлы для того, чтобы взаимодействовать с разными частями програм. Например для изменения счёта игрока из разных файлов.

Если бы они имели внутреннюю свяь, то это бы приводило к ошибкам повторного определения **при подключении к друним .cpp файлам**. Так как в двух файлах было бы одно и тоже определение.
Но внутреняя связь предотвращает это так как в каждый файл вставляется объявление с внутренней связью.


# Внешняя связь
Идентификаторы с внешней связью видны в других файлах
### Как указать внешнюю связь
- Функции и глобальные переменные имеют по умолчанию
- С помощью ключевого слова extern
```c++
extern const int a{ 10 }; // Константа будет видна в других файлах, но чтобы ее использовать, нужно выполнить предварительное объявление в других файлах
```
### Предварительное объявление глобальных переменных
Если переменная инициализирована в другом .cpp файле, а **не в .h**, то ее нужно предварительно объявить c помощью extern
```c++
// util.cpp
extern const int a{ 10 }; // extern служит для указания внешней связи и это слово не нужно при инициализации для не константных переменных
```
```c++
// main.cpp
#include <iostream>

extern const int a; // extern говорит, что переменная a внешняя. Тоесть мы не создаём новую переменную a, котора будет иметь внутреннюю связь в этом файле не смотря на то, что в другом файле у нее есть extern

int main() {
    std::cout << a;
}
```
Следует сравнить с этой записью:
```c++
// util.cpp
extern const int a{ 10 };
```
```c++
// main.cpp
#include <iostream>

const int a; // Привело бы к ошибке, так как мы не указали, что используем переменную a, которая объявлена гдето (не используем предварительное объявление) и компилятор думает, что мы создаём новую переменную (она будет иметь внутреннюю свзяь и не приведёт к ошибке нескольких определений) и не даём ей значение (константы требуют инициализатор).

int main() {
    std::cout << a;
}
```
Или сравнение с обычными переменными
```c++
// util.cpp
int a{ 10 }; // Не пишу extern так как эта переменная уже имеет внешнюю связь
```
```c++
// main.cpp
#include <iostream>

int a; // Повторное определение так как a в этом файле имеет сразу внешнюю связь
static int a; // Ошибки нет. Просто создаём новую переменную. Она имеет внутреннюю связь и не связывается с переменной из другого файла
extern int a; // Ошибки нет. Говорим, что это НЕ новое определение, а предварительное объявление

int main() {
    std::cout << a;
}
```
Для предварительного объявления функции слово extern не требуется.
Переменные с constexpr нельзя определять предварительно так как такое выражение требует инициализатора, а так как каждый файл компилируется по отдельности это приведет к ошибкам:
```c++
// util.cpp
extern constexpr int a{ 10 };
```
```c++
// main.cpp
#include <iostream>

extern constexpr int a; // Ошибка
extren int a; // Ошибка
extern const int a; // Сработает и значение будет 10
```


# Почему НЕКОНСТАНТНЫЕ глобальные переменные это зло
- Их может изменить любая функция. 
- Это усложняет отладку так как нужно пересматривать всю программу.
- Переменные из разных единиц трансляции могут инициализироваться в разном порядке. Например сначало могут инициализироваться переменные из logger.cpp, а потом из database.cpp, а может и наоборот
## Когда их стоит использовать
Можно использовать, если глобальная переменная соответствует как минимум этим двум критериям:
- Она хранит объект, который может быть только один во всей програме (Глобальный логгер, генератор случайных числел, конфигурация приложения)
- Этот объект используется практически в любом файле програмы
## Правильное использование глобальных переменных
Это применимо и к константным переменным
- Добавлять префикс g или g_ к переменным без пространста имён
- Поместить в отдельное пространство имён
- Инкапсулировать переменную (сделать ее доступной только из файла, в котором она объявлена) и предоставить функцию для работы с ней:
```c++
namespace Constants {
    constexpr duble gravity{ 9.8 };
}
double getGravity() {
    return Constants::gravity;
}
```
- Если функция использует глобальную переменную, нужно сделать так, чтобы функция не на прямую ее использовала, а получала через аргументы:
```c++
doube veliocity(int time, double gravity) {
    return time * gravity;
} // Использовать это

double veliocity(int time) {
    return time * Constants::gravity;
} // Вместо этого
```

# Встраеваемые функции и переменные
Предположим у нас есть такой код.
```c++
int sum(int a, int b) {
    return a + b;
}

int main() {
    std::cout << "2 + 2 = " << std::cout << sum(2, 2) << std::endl;
    std::cout << "3 + 3 = " << std::cout << sum(3, 3) << std::endl;

    return 0;
}
```
Тут есть недостатки. Каждый вызов функции незначительно снижает производительность. Так как процессору нужно:
- Запомнить адрес текущей выполняемой инструкции
- Создать и инициализировать параметры функций
- И так далее...
## Как это оптимизирует компилятор
Компилятор может выполнить встраивание кода. Это процесс, когда вызов функции заменяется кодом из её определения. Это будет выглядеть так:
```c++
int main() {
    std::cout << "2 + 2 = " << std::cout << 2 + 2 << std::endl;
    std::cout << "3 + 3 = " << std::cout << 3 + 3 << std::endl;

    return 0;
}
```
Это позволяет избежать не только выше перечисленных проблем, а ещё так как это теперь константное выражение 2 + 2 и 3 + 3 могут теперь вычислиться на этапе компиляции.
Компилятор обычно решает нужно ли так делать, так как в некоторых случаях это может навредить. Например каомпилятор может это не делать и изза того, что определение функции находится в другом файле.
## Ручнаое встраивание кода
Раньше компиляторы могли плохо определять нужно ли выполнять встраивание кода. Изза этого было добавлено ключевое слово inline. Оно позволяет подсказать компилятору, что возможно встраивание кода может помоч оптимизации. Компилятор в праве это проигнорировать
```c++
inline int sum(int a, int b) {
    return a + b;
}

int main() {
    std::cout << "2 + 2 = " << std::cout << sum(2, 2) << std::endl;
    std::cout << "3 + 3 = " << std::cout << sum(3, 3) << std::endl;

    return 0;
}
```
Сейчас использование этого слова считается плохим тоном. Так как это было всего лишь подсказкой и имело ещё недостатки в использовании.
## Современное использование ключевого слова inline
Данное слово позволет иметь несколько определений в разных единицах трансляции. Более того если у меня есть несколько таких определений, то память расходуется так как будто это одно определение. Это значит я могу определит функцию sum и в файле utils.cpp и в файле main.cpp
```c++
// utils.cpp
inline int sum(int a, int b) {
    return a + b;
}
```
```c++
#include <iostream>

inline int sum(int a, int b) {
    return a + b;
}

int main() {
    std::cout << sum(3, 3) << std::endl;
}
```
Это также позволяет безопасно писать определение функций в заголовочном файле.
### Требование к таким функциям
- Компилятор должен видеть полное определение функции в каждой еденице трансляции. Предварительного объявления не достаточно.
```c++
#include <iostream>

inline int sum(int a, int b); // Даже если определение есть в другом файле, использование этой функции в данном файле приведёт к ошибке так как нет определения.

int main() {
    std::cout << sum(3, 3) << std::endl;
}
```
- В каждой единицы трансляции функцию можно определять только один раз
```c++
#include <iostream>

inline int sum(int a, int b) {
    return a + b;
}

inline int sum(int a, int b) {
    return a + b;
} // Ошибка

int main() {
    std::cout << sum(3, 3) << std::endl;
}
```
- Определение может быть после использования, но должно все равно быть предварительное объявление. Однако в таком случае компилятор скорее всего не выполнит встраивание кода пока не увидит определение. Только выполнит встраивание кода в местах, которые идут после определения.
- Если функция имеет внешнюю связь, то ее определения должны быть идентичными иначе будет неопределённое поведение.
Следует избегать использования этого слова без веской причины (если определяю функции и переменные в заголовочных файлах).
Некоторые функции могут быть встраиваемыми по умолчанию. Например constexpr и consteval функции.
## Встраиваемые переменные
В C++17 появились встраиваемые переменные. Позволяют иметь несколько определений.
### Требования
- Компилятор должен видеть полное объявление в каждой единице трансляции
- В каждой единицы трансляции можно определять только один раз
Существуют переменные, которые являются встраиваемыми по умолчанию


# Способы использования глобальных констант в нескольких файлах
## Определение в заголовочном файле
```c++
// constants.h
namespace Constants {
    constexpr double pi{ 3.14 };
    constexpr double avogadro{ 6.02e23 };
}
``` 
```c++
// main.cpp
#include <iostream>
#include "constants.h"

int main() {
    std::cout << Constants::pi << std::endl;
}
```
### Недостатки данного подхода
- Каждый раз вместо #include "constants.h" вставляются определения констант. Это может нагружать память если они весят много.
- Изменение одной константы требует перекомпиляции каждого файла с #include "constants.h"
### Преимущества
- Использование до C++17
- Константы могут использоваться в постоянных выражениях
## Определение в .cpp и предварительное объявление через .h
```c++
// constants.cpp
namespace Constants {
    extern constexpr double pi{ 3.14 };
    extern constexpr double avogadro{ 6.02e23 };
} // Объявляем и устанавливаем внешнюю связь
``` 
```c++
// constants.h
namespace Constants {
    extern const double pi;
    extern const double avogadro;
} 
// Используем extern для "импорта" переменной (указываем что используем переменную с глобальной связью)
// Использование const вместо constexpr не приведёт к ошибке. Иначе програма не скомпилируется, но переменные не смогут использоваться в константных выражениях
``` 
```c++
// main.cpp
#include <iostream>
#include "constants.h"

int main() {
    std::cout << Constants::pi << std::endl;
}
```
### Недостатки данного подхода
- Переменные нельзя использовать в константных выражениях
### Приимущества
- Использование до C++17
- Есть только одна копия переменной, что экономит память
## Использовать inline в .h файлах
```c++
// constants.h
namespace Constants {
    inline constexpr double pi{ 3.14 };
    inline constexpr double avogadro{ 6.02e23 };
} // inline позволяет сделать так, что память будет использоваться как у одного объявления даже если будет много #include "constants.h" 
``` 
```c++
// main.cpp
#include <iostream>
#include "constants.h"

int main() {
    std::cout << Constants::pi << std::endl;
}
```
### Недостатки
- Изменение одной константы требует перекомпиляции каждого файла с #include "constants.h"
- Не работает до C++17
### Приимущества
- Экономия памяти
- Можно использовать в константных выражениях


# Статические локальные переменные
Клчевое слово static с локальными переменными даёт им статическую длительность. Это значит, что переменная создаётся в начале програмы и уничтожается в конце (как глобальная переменная). Это значит, что переменная сохранит свое значение при выходе из области видимости. Переменная продолжает иметь блочную область видимости.
```c++
#include <iostream>

void increment() {
    int a{ 0 };
    std::cout << a;
    ++a;

}

int main() {
    increment();
    increment();
    increment();
    
    return 0;
}
// В консоли будет 000.
```
```c++
#include <iostream>

void increment() {
    static int a{ 0 }; // Переменная статическая
    std::cout << a;
    ++a;

}

int main() {
    increment();
    increment();
    increment();
    
    return 0;
}
// В консоли будет 012
```
### Инициализация статических локальных переменных
Если нет начального значения или переменная имеет non-constexpr инициализатор, то она инициализируется нулями на старте програмы. Когда выполнее доходит до ее первого определеня они повторно инициализируются указанным значением. Определение пропускаются при последующих вызовах.

Если определение через {} (без значения в скобках) или если инициализатор constexpr, инициализация происходит при запуске при запуске.
## Добавления префикса
Статическим локальным переменным следует добавлять префикс s_.


# Повторение терменологии
## Область видимости
Это откуда можно получить доступ к идентификатору
### Локальная (блочная) область видимости
Доступны с момента объявления и до конца блока.
- Параметры функции
- Локальные переменные
### Глобальная область видимости
Доступны с момента объявления и до конца файла
- Глобальные переменные
- Функции
## Длительность
Когда переменная создаётся и уничтожается
### Автоматическая
Создаются в момент определения и уничтожаются при выходе из блока
- Параметры функции
- Локальные переменные
### Статическая
Создаются в момент запуска програмы и уничтожаются при завершении
- Глобальные переменные
- Статические локальные переменные
### Динамическая
Создаются и уничтожаются по запросу програмиста
- Динамически выделяемые переменные
## Связь
Будет ли объявление того же идентификатора в другой области видимости ссылаться на ту же сущность
### Не имеют связи
Каждое объявление ссылкается на уникальную сущность
- Локальные переменные
### Внутренняя связь
Объявление идентификатора **в одной и той же единице транслции** ссылается на одну и ту же сущность
- Статические глобальные переменные
- Статические функции
- Константные глобальные переменные
### Внешняя связь
Объявления одного и того же идентификатора **во всей программе** ссылаются на одну и ту же сущность
- Не статические функции
- Неконстантные глобальные переменные
- Внешние константные глобальные переменные
- Инлайновые константные глобальные переменные

Тут перечислены только то, что было изучено до этой главы
## Предварительное определение
Если нужно получить переменную и функцию из другого файла можно использовать предварительное объявление.
```c++
void increment(); // Предварительное определение функции
extern int a; // Предварительное определение глобальной переменной
extern const int a; // Предварительное определение константы. Может быть использовано для предварительного определения constexpr, но оно не будет constexpr в данной единице трансляции
extern constexpr int a; // Нельзя
```
Предварительно объявленные переменные имеют обычную область видимости:
```c++
int main() {
    {
        extern int a;
        std::cout << a;
    }

    std::cout << a; // Ошибка т.к. переменная в другом блоке при том что a в другом файле является глобальной
    return 0;
}
```
Следущий код также работает нормально:
```c++
#include <iostream>

extern int b;

int main() {

    std::cout << b; // 5
    return 0;
}

int b{ 5 };
```
## Спецификатор класса хранения
При использовании ключевых слов extern и static в качестве части объявления идентификатора их называют **спецификатором класса хранения**. В языке есть ещё несколько: mutable, auto, register, thread_local


# Using декларации и директивы
## Квалифицированные (полные) и неквалифецированные (неполные) имена
**Квалифицированное имя** - имя, содержащее квалификатор области видимости:
```c++
std::cout
::foo

Some_class::s_member
obj.x
ptr->y 
```
**Неквалифицированное имя** - не содержит квалификатора области видимости. Например просто cout или x
## Using декларации
Оператор using позволяет использовать неполное имя в качестве псевдонима для полного:
```c++
int main() {
    using std::cout; // Позволяет писать просто cout вместо std::cout. Но только для std::cout, а не всего std
    cout << "Hello world!" << std::endl;
}
```
Если возникнет конфликт между cout из std и другим cout. Предпочнение будет отдано тому, что из std в данном случае.
## Using директивы
Позволяет писать неполные имена для всего пространства имён
```c++
int main() {
    using namespace std;
    cout << "Hello world!" << endl;
}
```
### Почему следует избегать using namespace
- Включают имена, которые могут не использоваться в програме
- Не отдаёт предпочтение при конфликте указанному пространству имён
```c++
int cout() {
    return 5;
}

int main() {
    using namespace std;
    cout << "Hello world!" << endl; // Ошибка. Компилятор не знает какой cout использовать.
}
```
## Облась видимости слова using
Не действует в родительских или соседних блоках. Если написано в глобальной области видимости, то видно только в текущем файле.
## Не стоит использовать using там, где он может повлиять на код в других файлах
Например в заголовочных файлах или перед директивой include. И даже внутри функций в заголовочных файлах (это тоже имеет последствия):
```c++
using std::cout;
#include "utils.h" // Так как компилятор вставляет код из utils.h это повлияет на код в других файлах.
```


# Безымянные пространства имён
Пример объявления:
```c++
namespace {
    constexpr double pi{ 3.14 };
}
```
## Особенности
- Все, что объявлено внутри безымянного пространства имён рассматривается так, если бы они были объявлены в родительском пространстве имён (в данном случае в глобальном)
- Содержимое нельзя увидеть за пределами файла, в котором оно определлено

Тоесть в такое пространство можно поместить идентификаторы, которые должны иметь внутреннюю связь, чтобы не писать каждый раз static
## Предостирежения
Не нужно использовать такие пространства имён в заголовочных файлах


# Встроенные пространства имён
Позволяет делать так, что все что в неём объявлено является частью родительского пространства имёен, но в отличие от безымянного пространства имён сохранияет внешнюю связь.
```c++
#include <iostream>

inline namespace Library {
    constexpr double pi{ 3.14 };
}

int main() {
    std::cout << pi << std::endl;
    std::cout << Library::pi << std::endl; // Можно обращаться и с указанием имени пространства имён

    return 0;
}
```
Сохраняют внешнюю связь:
```c++
// main.cpp

#include <iostream>

inline namespace Library {
    extern constexpr double pi{ 3.14 };
}

int main() {
    std::cout << pi << std::endl;
    std::cout << Library::pi << std::endl;

    return 0;
}
```
```c++
// utils.cpp

#include <iostream>

inline namespace Library {
    extern const double pi;
}

void log() {
    std::cout << pi;
}
```
## Применение
Применяются для версионирования:
```c++
#include <iostream>

namespace V1 {
    void greet() {
        std::cout << "Hi" << std::endl;
    }
}

inline namespace V2 {
    void greet() {
        std::cout << "Hello" << std::endl;
    }
}

int main() {
    greet();

    return 0;
}
```
Допустим выпущена версия 1 и изначально встроенным является пространство имён V1. Функцию можно вызвать как с указанием пространства имён так и без и она будет ссылаться на одну и ту же. Затем я выпускаю версию 2 и уже делаю встроенным пространство имён V2. Тогда если пользователь использовал функцию без указания пространства имён, она обновиться, иначе будет старая версия.

# Встроенные безымянные пространства имён
Позволяют делать так, что все что в неём объявлено является частью родительского пространства имёен, но не позволяют получать доступ к содержимому из других файлов
```c++
// main.cpp

#include <iostream>

inline namespace {
    extern constexpr double pi{ 3.14 };
}

int main() {
    std::cout << pi;

    return 0;
}
```
```c++
// utils.cpp

#include <iostream>

inline namespace {
    extern const double pi;
}

void log() {
    std::cout << pi; // Ошибка
} 
```
Можно использовать и такую запись, тогда можно обращаться по имени
```c++
#include <iostream>

inline namespace Foo {
    namespace {
        constexpr double pi{ 3.14 };
    }
}

int main() {
    std::cout << Foo::pi << std::endl;
    std::cout << pi << std::endl;

    return 0;
}
```


# Оператор if и блоки
Запись оператора if:
```text
if (условие) {
    Выполняется если условие равно true
}

if (условие) {
    выполняется если условие равно true
} else {
    выполняется если условие равно false
}
```
Скоби (блоки) можно не использовать если нужно выполнить тольо одну строу кода, но компилятор всё равно неявно их использует, поэтому если там объявить переменную она всё равно не будет видна за приделами блока.
```c++
if (1 + 1 == 2)
    int x{ 5 }; // Не имеет смысла
```
Желательно всё равно всегда использовать блоки или размещать код на той же строке, где if или else:
```c++
if (true) {
    do_one_line();
}

if (true) do_one_line();
```
## Разница между if...else if и if... if...
```c++
if (a) {
    // ...
} else if (b) {
    // Проверка if (b) будет только если a ложно
} else if (c) {
    // Проверка if (c) будет только если b ложно
}

if (a) {
    // ...
}
if (b) {
    // Проверка if (b) будет всегда
}
if (c) {
    // Проверка if (с) будет всегда
}

// Второй пример не будет зависить от условия, ну если только там не будет к примеру return
```
## Проблемы с оператором if
Рассмотрим следущий код:
```c++
if (isRunning)
    // do something...
    if (isFetching)
        // do something...
else
    // do something..
```
Вопрос к какому if относится else. Ответ ко второму. Код выше аналогичен следущему:
```c++
if (isRunning) {
    // do something...
    if (isFetching) {
        // do something...
    } else {
        // do something...
    }
}
```
## Нулевые утверждения
**Нулевой оператор** - оператор выражения, состоящий только из точки с запятой. Оператор, который ничего не делает. Позволяет сделать блок if или что-то другое пустым:
```c++
    if (isRunning)
        ;
    else {
        // do something...
    }
```
Лучше помещать на отдельную строку, так как в ином случае его можно незаметить и подумать, что програма должна чтото делать:
```c++
if (isRunning);
do_something(); // Кажеться, что должно выполняться если условие верно
```
Эта запись напоминает ключевое слово pass в python. Его можно реализовать при помощи препроцессора:
```c++
#define PASS
if (isRunning) {
    PASS;
} else {
    // do something...
}
```


# Оператор if constexpr
В случаях, если условие является константным выражением можно использовать следущую запись:
```c++
constexpr double gravity{ 9.8 };

if constexpr (gravity == 9.8) {
    std::cout << "Gravity is normal" << std::endl;
} else {
    std::cout << "Gravity is NOT normal" << std::endl;
}
```
Во время компиляции компилятор оставит в данном случае только истинное выражение.
## Оптимизация non-constexpr условных операторов
Компилятор может рассмотреть обычный if оператор как константный, но это не является обязательным


# Оператор switch
Сравнивает результат указанного выражения с указанными вариантами:
```c++
switch (x) {
    case 1:
        // Выполниться если x == 1
    case 2:
        // Выполниться если x == 2
    default:
        // Выполниться в любом случае
}
```
Условие в данном операторе (x) должно иметь integral тип или перечисление.
## Метка default
В премере выше и вообще эта метка не обязательна, но выражение после нее выполниться в любом случае. Такая метка может быть только одна
## Return и break
Каждый набор операторов после метки должен оканчиваться оператором return или break. Это относится и к последней метке:
```c++
constexpr int x{ 10 };

switch (x) {
    case 1:
        std::cout << "X is 1" << std::endl;
        break;
    case 10:
        std::cout << "X is 10" << std::endl;
        break;
    default:
        std::cout << "Default block" << std::endl;
        break;
}

std::cout << "Hello world" << std::endl;
```
### Отличие return от break
**return** - Выход из функции (он не чем не отличается от использования в switch). Не будет выведено Hello world в данном случае.
**break** - Выход из оператора switch. В премере выше не будет выполнен даже default блок, так как мы полностью вышли из оператора. Будет выведено Hello world в данном случае.
## Когда использовать данный оператор
Стоит отдавать предпочтение данному оператору вместо if...else при проверке одного выражения (целочисленного, отличного от bool, или перечисления) на равенство небольшому набору значений


# Область видимости и проваливание у оператора switch
## Проваливание
Рассмотрим следущий код:
```c++
switch (1) {
    case 1:
        std::cout << 1 << std::endl;
    case 2:
        std::cout << 2 << std::endl;
    default:
        std::cout << "Default block" << std::endl;
}
```
Когда условие соответствует одной из меток case (в данном случае первой), выполнение начинается с первого оператора, следующего за соответствущей меткой. Выполнение будет продолжаться пока не произойдёт следующее:
- Будет достигнут конец блока switch
- Будет достигнут оператор return или break
Достижение другой метки не являеться условием завершения. Это значит, что код выше выведит следующее:
```text
1
2
Default block
```
Когда выполнение переходит от **оператора** под одной меткой к **операторам** под другой это называется **проваливание**
## Аттрибут [[fallthrough]]
Если происходит проваливание, компилятор может выдавать предупреждение. Если проваливание это намеренная цель, то при проваливании на следущую метку, в конце текущей метки нужно написать [[fallthrough]] (вместе с точкой с запятой (нулевой оператор)).
```c++
switch (1) {
    case 1:
        std::cout << 1 << std::endl;
        [[fallthrough]]; // Хочу провалиться во вторую метку, пишу [[fallthrough]]; в конце первой метки.
    case 2:
        std::cout << 2 << std::endl;
        break;
    case 3:
        std::cout << 3 << std::endl;
        break;
}
```
## Последовательные метки case
Функция ниже проверяет явяляется ли указанный символ гласной буквой.
```c++
bool isVowel(char c) {
    switch (c) {
        case 'a':
        case 'e':
        case 'i':
        case 'o':
        case 'u':
            return true;
        default:
            return false;
    }
}
```
Данный код использует последовательные метки case без операторов после них (метка не явлется оператором). Это не считается проваливанием.
## Объявление и инициализация переменных внутри switch
```c++
switch (1) {
    int a;
    int b{ 5 }; // Ошибка
    
    case 1:
        int c; // Нет ошиби
        a = 5;
        [[fallthrough]];
    case 2:
        std::cout << a << std::endl;
        break;
}
```
Внутри данного оператора можно объявлять и определять переменные как до так и после меток, но нельзя **инициализировать**.
Инициализация разрешена в последней метке (case или default). Это сделано потому, что если я к примеру инициализирую переменную в первой метке и захочу использовать во второй, то если условие будет соответствовать только второй метке, то я не смогу корректно ее использовать так как перепрыгну ее инициализацию, но в последней метке я могу инициализировать переменную так как дальше впринцепе не возможна такая ситуация чтобы я не мог нормально использовать переменную.
## Область видимости
Метки не создают новую область видимости.


# Оператор goto
Данный оператор позволяет выполнять переход к указанному месту в коде
```c++
int main() {
    int number{ 10 };
    int unswer;

    start: // Метка

    std::cout << "Угадай число" << std::endl;
    std::cin >> unswer;

    if (number == unswer) {
        std::cout << "Ты угадал!" << std::endl;
    } else {
        std::cout << "Попробуй ещё раз" << std::endl;
        goto start; // Говорим перейти к метке start
    }

    return 0;
}
```
Данная програма будет бесконечно спрашивать число пока пользователь не введёт 10. 
Метка оператора может находиться как перед ее использованием так и после
```c++
goto words;

std::cout << "Hello world!" << std::endl;

words:
std::cout << "Orange, banana, cat, dog" << std::endl;
```
В данном случае Hello world! не будет выведено на экран.
## Область видимости меток
Метки goto имеют **область видимости функции**. Это значит метка видна на протяжении всей функции даже до точки её объявления.
```c++
void greet() {
    greeting:
    std::cout << "Hello" << std::endl;
}

int main()
{
    greet();
    goto greeting; // Не могу перескочить в другую функцию
}
```
## Метка должна предшествовать оператору
Следующее выражение может вызвать предупреждение
```c++
void greet() {
    std::cout << "Hello" << std::endl;
    greeting: // После метки нет оператора
}
```
## Нельзя перепрыгивать через инициализацию переменной, которая всё ещё нахдится в области видимости в месте, куда вы прагаете
Следующий код вызывает ошибку:
```c++
goto greeting;
int a{ 5 };
greeting:
std::cout << "Hello world" << std::endl;
// Тут всё ещё существует переменная a
```
Следующий код уже не вызовет ошибок
```c++
goto greeting;
{
    int a{ 5 };
}
greeting:
std::cout << "Hello world" << std::endl;
// Переменная a не находиться в данной области видимости
```
## Стоит избегать оператора goto
Его стоит избегать так как он пораждает спагетти-код. Но есть некоторые исключения. Например если альтернативные варианты сильно ухудшают читаемость кода или например если нужно выйти из вложенного и внешнего цикла одновременно.
```c++
for (int i = 0; i < 10; i++) {
    for (int j = 0; j < 10; j++) {
        std::cout << i << " " << j << std::endl;
        if (j == 5) {
            goto end; // Если бы сдесь было написанно break, то выход был бы тольо из вложенного цикла, а так выходит и из внешнего
        }
    }
}
end:
std::cout << "Loop is ended" << std::endl;
```


# Цикл while
Позволяет выполнять код, пока условие верно
```text
while (условие) {
    // Код...
}
```
Код в фигурных скобках будет выполняться раз за разом, пока условие равно true.
## Бесконечный цикл
Если условие всегда возвращает true, то цикл является бесконечным. Для намеренно бесконечных циклов лучше сразу указывать true:
```c++
while (true) {
    std::cout << "Hello" << std::endl;
}
```
## Переменная цикла
Это переменная, которая используется для того, чтобы определить сколько будет итераций. Например:
```c++
int i{ 0 };

while (i <= 10) {
    std::cout << "Hello" << std::endl;
    i++;
}
```
В данном коде i является переменной цикла.
### Имена для переменной цикла
Наиболее распространённые это - i, j, k.
### Переменные цикла должны быть знаковыми
Следущий цикл будет бесконечным так как, когда i должна будет стать отрицательной, она переполнится и будет большое положительное число:
```c++
unsigned int i{ 0 };

while (i <= 0) {
    std::cout << "Hello" << std::endl;
    i++;
}
```
## Циклы можно вкладывать друг в друга
```c++
int i{ 0 };
int j{ 0 };

while (i <= 10) {
    while (j <= 10) {
        std::cout << i << " " << j << std::endl;
        j++;
    }
    i++;
}
```


# Цикл do...while
Цикл do...while работает аналогично циклу while за исключением того, что он сначало выполнит как минимум одну операцию, а только потом проверит условие и если условие вернёт false то он не будет выполнять вторую итерацию, но первую выполнит в любом случае
```c++
int i{ 0 };

do {
    std::cout << "Hello" << std::endl;
    i++;
} while (i <= 10)
```
По возможности лучше использовать обычный while если только в ином случае это не ухудшает читаемость кода


# Цикл for
```text
for (Начальное выражение; условие; конечное выражение) {
    // Тело цикла (то, что будет повторяться)
}
```
Сначало выполняется начальное выражение (тут инициализируется переменная цикла), затем если условие верно выполняется итерация и наконец выполняется конечное выражение (тут обычно увеличивается или уменьшается переменная цикла) затем снова проверяется условие:
```c++
for (int i{ 0 }; i <= 10; i++) {
    std::cout << "Hello world" << std::endl;
}
```
В данном примере мы инициализируем переменную i, затем устанавливаем условие, а затем увеличиваем ее после каждой итерации. Данная переменная видна только в теле цикла, в начальном выражении, в условии и в конечном выражении
## Пропуск выражений и условия
Мы можем вообще ничего не писать если нам не нужно условие или выражение:
```c++
int i{};

for (; i <= 10; i++) {
    std::cout << i << std::endl;
}
```
В данном примере я объявил переменную вне цикла (плохая практика)
```c++
for (;;) {
    std::cout << "Hello" << std::endl;
}
```
Это вообще будет бесконечный цикл
## Несколько счётчиков
Данный код абсолютно рабочий и не считается плохой практикой:
```c++
for (int x{}, y{}, x <= 10; ++x, --y) {
    std::cout << x << " " << y << std::endl;
}
```
В конечном выражении используется оператор запятая


# Break и continue
## Оператор break
Данный оператор также позволяет выйти из любого цикла в любой момент:
```c++
for (int i{}; i <= 10; i++) {
    if (i == 5) {
        break;
    }
}
```
Цикл закончиться как только i станент равной 5
## Оператор continue
Данный оператор позволяет прервать **текущую итерацию** цикла и перескочить на следующую. Стоит обратить внимание, что конечное выражение всё равно выполниться
```c++
for (int i{}; i <= 10; i++) {
    if (i == 5) {
        continue; // Переходим на следующую итерацию
    }
    std::cout << i << std::endl;
}
```
В данном случае будут выведены числа от 0 до 10 за исключением 5


# Преждевременный выход из программы
Когда завершается функция main (из-за return), вызывается специальная функция std::exit, в которую передаётся возвращаемое значение функции main. std::exit выполняет ряд очисток, например уничтожение переменных со статической длительностью, аргумент, переданный функции std::exit, используется для статус-кода завершения программы.
Функция std::exit относится к halt операторам. Это операторы, которые завершают управление потоком.
## Явный вызов std::exit
```c++
#include <cstdlib> // Подключаем заголовок для std::exit
#include <iostream>

int main() {
    std::exit(0); // Можно вызвать в любой функции
    std::cout << "Hello world!" << std::endl; // Не выведится
}
```
## Функция std::exit не уничтожает локальные переменные
Функция std::exit не уничтожает локальные переменные ни в текущей функции, ни в стеке вызовов
## Функция std::atexit
Данная функция позволяет зарегестрировать функцию для очистки, которая будет вызываться при вызове std::exit. Можно регестрировать несколько функций, но не за раз. Они будут вызываться в обратном порядке.
Под функцией для очистки подразумевается функция, которая закрывает соединения с сервером, закрывает файлы, вызовы delete и т.д.
```c++
#include <iostream>
#include <cstdlib>

void close_connection() {
    std::cout << "Закрытие соединения..." << std::endl;
}

void close_logs() {
    std::cout << "Закрытие лог-файлов..." << std::endl;
}

int main() {
    std::atexit(close_connection);
    std::atexit(close_logs);

    std::exit(0);
}
```
Функция очистки не должна ничего возвращать и не должна принимать аргументы.
Хотя обычно операционные системы сами очищают память, всё равно это является хорошим тоном по нескольким причинам.
## Функции std::abort
Функция std::abort вызывается разработчиком, при критических ошибках. Данная функция не выполняет никакой очистки
```c++
#include <cstdlib>

int main() {
    std::abort();
}
```
## Когда использовать halt
Почти никогда. Их нужно использовать только в исключительных случаях. В других случаях лучше воспользоваться исключениями.


# Введение в генерацию случайных чисел
По своей природе компьютер не может выдавать случайное число. Поэтому он генерирует псевдослучайные числа при помощи алгоритма
## Алгоритм, состояние алгоритма, детерминированный алгоритм
**Алгоритм** - конечная последовательность инструкций, которую можно выполнить для решения задачи.
Ниже представлен алгоритм, который каждый раз увеличивает заданное начальное число на 1:
```c++
#include <iostream>

int plusOne() {
    static int s_state{ 3 }; // Задаём 3 в качестве начального значения
    ++s_state;

    return s_state;
}

int main()
{
    std::cout << plusOne() << std::endl;
    std::cout << plusOne() << std::endl;

    return 0;
}
```
**Алгоритм считается сохраняющим состояние** - если он сохраняет некую информацию мжду вызовами.
Данный алгоритм считается сохраняющим состояние так как он сохраняет значение переменной s_state.
**Алгоритм считается детерминированным** - если он выдаёт всегда одну и туже последовательность выходных данных при одинаковых входных данных.
Данный алгоритм детерминирован.
## Генераторы псевдослучайных чисел (ГПСЧ)
Ниже представлен алгоритм, который генерирует псевдослучайные числа:
```c++
#include <iostream>

unsigned int randnum() {
    static unsigned int s_state{ 0 };

    s_state = 83569 * s_state + 78932; // Изменяем состояние при помощи любых цифр и операций

    return s_state % 32768;
}

int main()
{
    for (int i{ 0 }; i <= 16; i++) {
        std::cout << randnum() << std::endl;
     }

    return 0;
}
```
## Инициализация ГПСЧ
Генератор в примере выше остаётся детерминированным. Если запустить программу 3 раза, то последовательности будут одинаковы. Поэтому можно запросить у пользователя начальное значение.
```c++
#include <iostream>

unsigned int g_state{ 0 };

void setSeed(unsigned int seed) {
    g_state = seed;
}

unsigned int randnum() {
    // Не используем статическую переменную так как используем глобальную
    g_state = 83569 * g_state + 78932; 

    return g_state % 32768;
}

int main()
{
    setSeed(20); // Устанавливаем пользовательское значение

    for (int i{ 0 }; i <= 16; i++) {
        std::cout << randnum() << std::endl;
     }

    return 0;
}
```
## Качество сида и подсев
Чтобы прогама выдавала каждый раз различные последовательности, начальное значение должно быть разным при каждом запуске. Просить пользователя ввести его не лучший вариант, так как он может воодить всегда одинаковые начальные значения. Для этого используются алгоритмы, генерации начального значения.
### Максимальное количество уникальных последовательностей
Теоритически максимальное количество уникальных последовательностей, которые может сгенерировать ГПСЧ, определяется количеством битов в начальном значении. Например, если начальное значение содержит 128 битов, то макисмальное количество уникальных последовательностей = 2^128
Но конечно это ещё зависит от алгоритма генерации начального значения. Если алгоритм может выдать только 4 уникальных значения, то только 4 уникальные последовательности могут быть сгенерированы при помощи ГПСЧ
Тоесть если начальное значение 4 битное число, макимальное количество уникальных чисел = 2^4 = 16. Соответствено в теории ГПСЧ может выдать 16 уникальных последовательностей, но если алгоритм генерации начального значения будет выдавать только 4 и 7 (они также будут четырёхбитные), то соответственно ГПСЧ выдаст только 2 уникальные последовательности.
### Недостаточно инициализированный ГПСЧ
Если ГПСЧ передан некачественный сид, то говорят, что он **недостаточно инициализирован**.
Например, сид очень предсказуем
В таком случае может происходить следующее
- Можно угадать начальное значение ГПСЧ по выходным псевдослучайным случайным числам
- Некоторые значения могут не генерироваться вообще
- Програма будет выдавать похожие наборы чисел, если её запустить несколько раз 
### Идеальный сид
- Начальное значение должно содержать столько же битов, сколько и состояние ГПСЧ. Иначе будет меньше уникальных последовательностей.
- Каждый бит в сиде должен не зависить от соседних. Так как случайность нарушается и становится легче угадать сид.
- В сиде должно быть поровну 0 и 1 и они должны быть хаотично разбросаны, иначе многие ГПСЧ будут выдавать плохо перемешанные значения.
- В сиде не должно быть битов, которые почти никогда не изменяются (например год, если в качестве сида брать дату), так как они не несут новой случайности, соответственно будет меньше уникальных последовательностей.
- Новый сид не должен быть похож на предыдущий. Это приведет к генерации похожих последовательностей в разных програмах
На практике приходится идти на компромисс с некоторыми характеристиками.
## Рандомизация в C++
Для использования рандомизации в C++, нужно подключить заголовочный файл random. Там есть множество семейств. Есть абсолютно устаревшие, которые вообще не стоит использовать. Они есть лишь для совместимости с C. Самым лучшим из них, начиная с C++20 является алгоритм Mersenne Twister. Однако он имеет недостаток: его результаты можно предсказать, увидем 624 сгенерированных числа, поэтому для написания чего-то серьёзного потребуется использовать сторонние библиотеки.


# Введение в тестирование кода
**Тестирование ПО** - процесс определения того, действительно ли ПО работает как ожидается.
## Задача тестирования
На самом деле совсем всесторонне протестировать программу почти невозможно. Рассмотрим следующую программу:
```c++
#include <iostream>

int main() {
    int a{};
    int b{};

    std::cin >> a;
    std::cin >> b;

    if (a > b) {
        std::cout << "A is bigger than b" << std::endl;
    }
    return 0;
}
```
В теории для полноты теста нужно прогнать через программу все омбинации со всеми возможными int числами, что очень очень много. Но на самом деле достаточно проверить 2 комбинации, где a больше и наоборот. Существуют другие приёмы, которые позволяют сократить количество проверок.
## Тестировать программу нужно небольшими фрагментами
Подобно сборке автомобиля, мы сначало будем тестировать каждую его деталь по отдельности перед сборкой. Чтобы сразу понять какая деталь не исправна. Так и в прогремме. Код нужно писать небольшими функциями, классами и тестировать каждую функцию, класс и т.д. по отдельности после написания.
## Неформальное тестирование
Допустим мы написали функцию для проверки символ гласный или нет. Затем мы можем сразу же написать тест, а потом его удалить из кода
```c++
bool isLowerVowel(char c) {
    switch (c) {
        case 'a':
        case 'e':
        case 'i':
        case 'o':
        case 'u':
            return true;
        default:
            return false;
    }
}

int main() {
    // Сразу же пишем тесты
    std::cout << isLowerVowel('a') << std::endl;
    std::cout << isLowerVowel('b') << std::endl;

    return 0;
}
```
## Сохранение тестов
Тесты может быть полезно сохранять. Допустим мы расширим функционал или переделаем функцию isLowerVowel и нам снова понадобиться протестировать функцию. Наш тест можно даже вынести в отдельную функцию testVowel:
```c++
void testVowel() {
    std::cout << isLowerVowel('a') << std::endl;
    std::cout << isLowerVowel('b') << std::endl;
}
```
## Автоматизация тестовых функций
Можно сделать так, чтобы функция возвращала 0, если всё хорошо, иначе вернёт номер проваленного теста. К тому же в примере ниже не придётся помнить каждый раз какой результат правильный, а какой нет, так как мы это укажем в коде.
```c++
int testViwel() {
    if (!isLowerVowel('a')) {
        return 1; // Мы сразу в коде указали, что если если isLowerVowel вернёт false, с аргументом a, то это не правильно и вернётся номер проваленного теста
    }
    if (isLowerVowel('b')) {
        return 2;
    }
    
    return 0;
}
```
Лучше будет использовать функцию assert из заголовочного файла cassert. Если в качестве аргумента такой функции передать false, то она немедленно прирвёт выполнение программы и выведит диагностическое сообщение в поток ошибок, которое содержит выражение, которое вернуло false и другие данные.
```c++
#include <cassert>

int testVowel() {
    assert(isLowerVowel('a'));
    assert(!isLowerVowel('b'));

    return 0;
}
```

## Интеграционное тестирование
После модульного тестирования проводят интеграционное тестирование. Это процесс при котором тестируют уже объединённые модули для того чтобы убедиться, что они корректо взаимодействуют между собой.

# Покрытие кода
Данный термин используется для того какая часть програмы тестируется во время тестирования
## Покрытие операторов
Рассмотрим следующий пример
```c++
int foo(int x, int y) {
    int z{ y };

    if (x > y) {
        z = y
    }
    
    return z;
}
```
Если мы вызовем функцию именно как foo(1, 0), то это обеспечит полное поерытие всех операторов внутри нее. Так как будут выполнены все операторы.
Для полного покрытия операторов функции isLowerVowel из прошлого урока понадобится два вызова: один с гласной буквой, другой с согласной.
## Покрытие ветвей
Например есть следующий код:
```c++
void compare(int x, int y) {
    if (x > y) {
        std::cout << "X > Y" << std::endl;
    } else if (x < y) {
        std::cout << "X < Y" << std::endl;
    } else {
        std::cout << "X = Y" << std::endl;
    }
}
```
Для полного покрытия данных ветвей потребуется вызвать функцию compare 3 раза.
Следует стремиться к 100% покрытию ветвей.
## Покрытие циклов
Иногда его нефофициально называют тест 0, 1, 2. Это значит, что если есть цикл, то для его покрытия достаточно убедиться, что он корректно работает при 0, 1 и 2 итерациях.
```c++
void spam(int iterations) {
    for (int i{0}; i <= iterations; i++) {
        std::cout << "Spam!" << std::endl;
    }
}
```
Достаточно вызвать функцию spam 3 раза. С 0, 1, 2 в качестве аргумента
## Тестирование различных категорий входных данных
В данном контексте категория, обозначает набор входных данных, имеющих схожие характеристики.
Вот несколько советов:
- При работе с целыми числами стоит убедиться как функция работает с отрицательными, положительными числами и нулём. Проверить наличие переполнения. Например передать 0.1 так как это число немного больше чем стоит ожидать, а 0.7 меньше ожидаемого
- Для чисел с плавающей запятой стоит убедиться как функция обрабатывает значения с проблемами точности.
- При работе со строками, стоит убедиться как функция обпабатывает строи из букв, из цифр и букв, строки с пробелами

# Выявление и обработка ошибок
При тестировании нужно тестировать не только счастливый сценарий, но и печальный. Тоесть тестировать что будет, если будет ошибка.
## Обработка ошибки внутри функции
Ошибку желательно локализовать. Тоесть обработать или исправить ее в той же функции, где она произошла, чтобы дальше всё работало нормально.
Например если функция должна распечатать результат деления, при возникновении диления на 0 не выбрасывать ошибку вызывающей стороне, а разобраться с этим сразу в функции:
```c++
void pintDivision(int x, int y) {
    if (y != 0) {
        std::cout << x / y << std::endl;
    }
}
```
## Передача ошибок вызывающей стороне
Не всегда бывает целесообразно обрабатывать ошибку внутри функции. Например, если функция должна вернуть результат деления:
```c++
int division(int x, int y) {
    return x / y;
}
```
Например, если функция возвращает только пределённый диапозон значений, некоторые значения можно сделать контрольными, тоесть такими, которые имеют определённый статус.
```c++
constexpr error_non_reciprocal{ 0.0 };

double recipocal(double x) {
    if (x == 0) {
        return error_non_reciprocal;
    }
    
    return 1 / x;
}
```
Ещё можно немного модифицировать функцию printDivision, чтобы она возвращала булево значение, которое будет как статус-код функции:
```c++
bool printDivision(int x, int y) {
    if (y == 0) {
        std::cout << "Error" << std::endl;
        return false;
    }

    std::cout << x / y << std::endl;
    return true;
}
```
Так как функция выше никогда не должна возвращать 0, можно сделать так, что если функция вернула 0, то это ошибка.
## Фатальные ошибки
Если ошибка серьёзная и программа не может корректно работать, то лучше завершить программу. Если мы находимся в main, то лучше позволить ей вернуть код состояния отличный от 0. Если мы находимся глубоко во вложенной функции, распространение ошибки до main может быть трудным, то лучше использовать halt выражение, например, std::exit.
## std::cout vs std::cerr
Обе эти програмы позволяют выводить текст в конслоль, но std::cerr не использует буферизацию.

Следует выделить два типа приложений. Интерактивные - взаимодействуют с пользователем после запуска. Например, игры, музыкальные приложения и т.д. Неинтеративные - не требуют взаимодействия с пользователем после запуска. Их результат выполнения может использоваться другими програмами. Например это скрипты, антивирусы, команда grep в Unix.
### Когда использовать std::cout
- Обычный текст, который важен пользователю
- Сообщения об ошибках, например, непраильный ввод имени
### Когда использовать std::cerr
- Информация о состоянии приложения, которая может быть полезна для выявления проблем, но не предоставляет интерес для обычных пользователей. Технические предупреждения, обновление статуса, неверный ввод в функцию
- Вывод ошибок для неинтерактивных программ. Например, не удалось открыть файл
- Вывод событий для любого типа приложения, имеющего транзакционный характер. Информация о проценте выполнения, какой файл обрабатывается


# Обработка недопустимого ввода
## Пример програмы
Рассмотрим пример программы:
```c++
#include <iostream>

double getDouble() {
    std::cout << "Enter a decinal number: ";

    double x{};
    std::cin >> x;

    return x;
}

char getOperation() {
    std::cout << "Enter an operation (+, -, *, /): ";

    char operation{};
    std::cin >> operation;

    return operation;
}

void printResult(double x, double y, char operation) {
    std::cout << x << " " << operation << " " << y << " is ";

    switch(operation) {
        case '+':
            std::cout << x + y;
            return;
        case '-':
            std::cout << x - y;
            return;
        case '*':
            std::cout << x * y;
            return;
        case '/':
            std::cout << x / y;
            return;
    }
}

int main() {
    double x{getDouble()};
    char operation{getOperation()};
    double y{getDouble()};

    printResult(x, y, operation);

    return 0;
}
```
Можно выделить 4 типа некорректного ввода текста:
- Извлечение данных прошли успешно, но они не имеют смысла. Например, ввод буквы k в качестве математического оператора
- Извлечение прошло успешно, но пользователь вводит дополнительные данные. Например, *q в качестве математической операции. Символ q будет в буфере.
- Не удаёться извлечь данные. Например, ввод q в числовое поле.
- Извлечение произошло успешно, но пользователь ввёл данные, привышающие предел. Например, ввёл слишком большое число.
## Первый случай
Нам нужно проверять значение, пока пользователь не введёт правильное значение:
```c++
char getOperation() {
    while(true) {
        std::cout << "Enter an operation (+, -, *, /): ";

        char operation{};
        std::cin >> operation;

        switch(operation) {
            case '+':
            case '-':

            case '/':
                return operation;

        }
    }

```
## Второй случай
Предположим пользователь в нашей программе введёт 4+5. Программа выполнится корректно так как сначало считается 4, а остальные символы будут в буфере. И по мере выполнения программы они извлекуться из буфера. Хоть пограмма будет работать, но консоль будет выглядеть некрасиво так как не будет видно введёных символов в месте ввода операции и второго числа. Стоит обратить внимание, что это сработает только если порядок вызовов функций будет такой:
```c++
double x{getDouble()};
char operation{getOperation()};
double y{getDouble()};
```

## Обработка EOF
EOF расшифровывается как End Of File - это особое состояние ошибки, указывающее, что нет данных ввода. Например оно будет если попытаться считать дополнительные данные после достижения конца файла.

Если попытаться извлеч ввод из std::cin, а его не будет, то будет ошибка EOF. Да, по идее программа будет ждать, пока пользователь введёт данные, но std::cin может сгенерировать данную ошибку, если ввести специальную комбинацию клавиш. Ctrl + d в Unix.

Поведение после ввода EOF зависит от операционной системы. Хотя std::cin.clear() устранит ошибку, но поток будет закрыт и мы не сможет извлеч данные во второй итерации. Вот как выглядит исправленный код:
```c++
bool clearFailedExtraction() {
    if (!std::cin) {
        if (std::cin.eof()) {
            std::exit(0);
        }
        
        std::cin.clear();
        ignore();
        
        return true;
    }
    
    return false;
}

double getDouble() {
    while (true) {
        std::cout << "Enter a decinal number: ";

        double x{};
        std::cin >> x;

       if (clearFailedExtraction()) {
            std::cout << "Invalid input" << std::endl;
            continue;
       }
       
       ignore();
       return x;
    }
}
```

# Assert и static_assert
Утверждение (assertion) - это выражение, которое которое будет истинным если в программе нет ошибки. Если оно оценивается как false, программа должна приврать работу и показать сообщение об ошибки.

Утверждение используются для обнаружения ошибок во время **разработки** и или **отладки**.
## Assert
```c++
#include <cassert>
assert(gravity > 0.0);
```
Программа ниже завержится если значение gravity будет меньше нуля. Так как в ином случае программа будет работать не корректно.

Assert вызовет std::abort и в консоль будет выведено сообщение об ошибке.
## Как сделать сообщение более информативным
```c++
assert(found); // Не понятно, что именно найдено
assert(found && "URL not found"); // Сообщение проигнорируется если found истина так как оба операнда истина и соответственно ничего не будет, в ином случае, если found ложь, а строка это всегда истина, то выражение вернёт ложь. В таком случае в консоль выводится все выражение, которое находится в аргументе assert
```
## Указание, что функция не реализована
Assert можно использовать чтобы указать, что функция не реализована.
```c++
assert(moved && "Need to handle case where student was just moved to another classroom");
```
Тут показано, что ещё нет, кода, который обрабатывает движение.
## NDEBUG
Позволяет включать и выключать assert.
```c++
#define NDEBUG // Assert не будет работать
#undef NDEBUG // Assert будет работать

// Данные объявления должны идти перед любыми #include
```
## Static_assert
Данное **ключевое слово** работает похоже на assert, но оценивает выражение во время компиляции и принимает константное выражение. Для его использования не нужно подключать заголовки.
```c++
static_assert(sizeof(long) == 8, "long must be 8 bytes"); // Если размер типа long равен 8 байт, то ничего не будет, иначе выведет ошибку в консоль и сообщения об ошибке из второго аргумента.
```
До C++17 второй аргумент был обязателен.

Стоит отдавать предпочтение static_assert вместо assert.
## Когда использовать утверждения, а когда обрабатывать ошибки
Утверждения стоит использовать для тестирования кода. Утверждения не должны быть в продакшн сборке. Они нужны только для выявления ошибок в программе.

Поверять ошибки стоит тогда, когда ошибка действительно может быть в продакшн сборке. Например если пользователь вводит строку вместо числа.

Иногда можно комбинировать подход. Например рассмотрим функцию ниже:
```c++
double getInverse(double x)
{
    assert(x != 0.0);
    if (x == 0.0)

    return 1.0 / x;
}
```
Тут мы используем assert, для того чтобы тестировать код, но также обрабатываем ошибку если все же в теории есть шанс, что в продакшн сборке есть шанс, что будет ошибка. 

Тоесть стоит использовать оба варианта если мы не хотим, что бы ошибка произошла, но если это будет мы должны корректно обработать этот случай.

## Суть преобразования
Каждое значение в памяти храниться в виде битов. Каждый тип представляет свое значение по разному. Например, int 3 и double 3 используют разный набор битов, так как double должен хранить ещё и дробную часть. Изза этого компилятор не может просто скопировать биты там, где нужно преобразование
```c++
float f{ 3 }; // Компилятор не может просто скопировать биты, представляющие int 3, так как float интерпритировал их как совсем другое значение
```
## Стандартные преобразования
Это набор правил, которые встроены в компилятор, в которых указано как одни типы преобразуються в другие. Есть несколько категорий этих правил
## Преобразования типов могут завершиться неудачей
Иногда компилятор просто не значет как преобразовать один тип в другой
```c++
int x{ "14" }; // Ошибка, так как не существует стандартного преобразования строкового литерала в int
```
Также в некоторых случаях, хоть компилятор и умеет преобразовывать double в int, он этого не сделает изза потери данных
```c++
int x{ 3.14 }; // Будет потеряна дробная часть
int x = 3.14; // Сработает, но переменная будет хранить только целую часть
```

# Integral повышение и повышение чисел с плавающей точкой
Каждый тип в C++ фактически может иметь разный размер в зависимости от компилятора и архитектуры. Это сделано для того, чтобы типы int и double имели размер, с которым процессору будет легче работать. Например, 32 битному компьютеру будет легче работать с 32 битными данными чем с 16 битными.
## Числовое повышение
**Числовое повышение** - это преобразование более узких числовых типов в более широкие (обычно int и double), чтобы они обрабатывались более эффективно. Такие преобразования считаються безопасными, так как сохраняют данные.
### Integral продвижение
Представляет из себя конвертацию более узкого inegral типа в более широкий, который ускоряет работу с типом. Например конвертация char, который занимает меньше битов в int, который будет обрабатываться процессором быстрее, чем char. Помимо этого, повышение позволяет уменьшать избыточность. Рассмотрим пример ниже:
```c++
void print_number(int x) {
    std::cout << x << std::endl;
}

print_number('c');
```
В данном примере я передал char в функцию, которая принимает int. Если бы не существовало числового повышения мне бы пришлось писать функцию под каждый тип. В данном случае компилятор просто преобразовал более узкий тип в более широкий.
### Повышение чисел с плавающей точой
Подобная вещь есть и для чисел с плавающей точкой. Компилятор преобразует float в double для более эффективной обработки и также снижается избыточность:
```c++
void print_double(double x) {
    std::cout << x << std::endl;
}

print_double(10.0f);
```
В функцию, которая принимает тип double я передаю тип float, который уже, чем double.
## Знаковость после повышения
В некоторых случаях знаковость числа после повышения может не сохраняться.
## Числовые преобразования
Не все преобразования из более узкого типа в более широкий являются числовыми повышениями. Например, char в short или int в long не являются таковыми. Они являються числовыми преобразованиями так как они не преобразуют меньший тип в больший, для того, чтобы обработка проходила **более эффективно**.
## Зачем тогда нужны более узкие типы, кроме int
Дело в том, что числовое повышение происходит только во время вычислений. Данные все равно храняться, как указанный тип и занимают меньше памяти, чем int.


# Числовые преобразования
## Типы числовых преобразований
- Преобразование инегрального типа в любой другой интегральный тип (за исключением интегрального повышения)
```c++
short s = 3; // int 3 -> short
long l = 3; // int 3 -> long
char c = s; // short s -> char
unsigned int u = 3; // int 3 -> unsigned int
```
- Преобразование типа данных с плавающей запятой в любой другой тип данных  сплавающей запятой (за исключением повышения чисел с плавающей запятой)
```c++
float f = 3.0; // double 3.0 -> float
long double l = 3.0; // double 3.0 -> long double
```
- Преобразование числа с плавающей точкой в любой интегральный тип
```c++
int i = 3.5; // double 3.5 -> int
```
- Преобразование интегрального типа в любой тип с плавающей запятой
```c++
double d = 3; // int 3 -> double
```
- Преобразование интегрального типа или типа с плавающей запятой в логический тип bool
```c++
bool b = 3.0; // double 3.0 -> bool
```
## Безопасные и небезопасные преобразования
Есть несколько категорий безопасности числовых преобразований
- **Преобразования с сохранением значений** - безопасные числовые преобразования. При котором целевой тип может представить все значения исходного типа. Тип может быть спокойно преобразован туда и обратно.
```c++
int n{ 5 };
long l = n; // Преобразование int в long. В long можно конвертировать любое int значение
```
- **Переинтерпретированые преобразования** - небезопасные числовые преобразования, при которых преобразованное значение может отличаться от исходного, но данные при этом не теряються. Например преобразование signed int в unsigned int.
```c++
int i{ -5 };
unsigned int ui{ i }; // Произойдёт переполнение, но данные можно восстановить если конвертировать обратно в signed int
int x{ ui }; // Будет -5
```
- **Преобразование с потерями данных** - небезопасное преобразование, при котором данные могут быть потеряны.
```c++
int x = 3.5; // Потеряем дробную часть
float f = 1.23456789; // Потерем часть дробной части так как она не поместиться в float
```
Обычно преобразование int в double считаеться безопасным так как int занимает 4 байта, а doube 8, но на некоторых архитектурах они оба могут занимать 8 байт изза этого может потерться часть данных.

По возможности следует избегать небезопасных преобразований, но иногда они допустимы, например преобразовать int в bool или если мы сами контролируем диапозон значений, что при конвертации int в unsigned int оно не отрицательно, например ради оптимизации.


# Арифметические преобразования
```c++
int x{ 1 + 1 };
```
В данном примере operator+ получает операнды одинакового типа, который и будет использован во время вычисления и возвращаемое знаение будет иметь этот же тип.
```c++
int x{ 5.1 + 5 };
```
В данном случае операнды имеют разный тип и должны будут быть преобразованными с использованием правил под названием арифметические преобразования. Тип, полученный после преобразовани называеться **общий тип** операндов.
## Операторы, требующие операндов одного типа
- Бинарные арифметические операторы (+, -, *, /, %)
- Бинарные операторы сравнения (<, >, ...)
- И так далее...

К перегруженным операторам не применяются обычные правила арифметического преобразования
## Обычные правила арифметического преобразования (упрощено)
Есть список типов, который отранжирван от высшего к меньшему. Тип меньшего ранга будет преобразовываться в тип большего ранга:
- long double (Высший ранг)
- double
- float
- long long
- long
- int (Низший ранг)
Тоесть если есть к примеру int и double, то int превратиться в double и при этом не будет такого, что все превратяться в long double. Если же все операнды уже чем int, то произойдёт интегральное повышение и все станут int.

### Преобразование знаковых и беззнаковых операндов 
1. unsigned ранг >= signed ранг -> signed превращаеться в undigned
2. весь диапозон unsigned помещаеться в диапозон signed -> unsigned превращаеться в signed
```c++
unsigned short x{ 5 }; // Беззнаковое число
long long y{ 25 }; // Знаковое число

5 + 25; //  Компилятор видет, что диапозон unsigned short легко поместиться в диапозон long long и преобразует все в signed. На это не влияет знак самого значения. Тоесть если бы y был -25 все работало бы также
```
3. В противном случае оба преобразуються в unsigned

# Явное преобразование типов (приведение типов)
## Виды приведений типов
Существует несколько видов приведения типов:
- static_cast
- dynamic_cast
- const_cast (Следует избегать)
- reinterpret_cast (Следует избегать)
- Приведение типов в стиле C
## Приведение типов в стиле C
```c++
int x{ 10 };
int y{ 4 };

std::cout << (double)x / y << std::endl; // Приводим x к значению double и в итоге происходит деление чисел с плавающей запятой, а не целочисленное деление

std::cout << double(x) / y << std::endl; // Тоже самое, что и пример выше
```
Следует избегать приведения типов в сителе C, так как оно не указывает, какое именно преобразование выполняеться (статическое или константное и т.д) и ещё по ряду причин.
## static_cast
Данное приведение следует использовать в большинстве случаев. Вот пример выше, но использующий статическое приведение:
```c++
std::cout << static_cast<double>(x) / y << std::endl;
```
В угловые скобки запичываеться тип, к которому нужно привести, а в круглые выражение, которое нужно привести.

Поскольку static_cast работет на этапе компиляции, он позволяет на этапе компиляции выдавать ошибку, если тип невозможно привести:
```c++
static_cast<int>("Hello");
```
### Избегание предупреждений
Компилятор может выдавать предупреждение если преобразование типа небезопасно:
```c++
int x{ 5 };
char c{ x }; // Предупреждение о сужающем преобразовании
```
Явное преобразование не будет вызывать предупреждений:
```c++
int x{ 5 };
char c{ static_cast<char>(x) }; // Так как само преобразование не будет вызывать предупреждений, а c инициализируеться уже типом char
```
## Приведение с использованием временного объекта
```c++
std::cout << double{x} / y << std::endl; // double{x} создаёт временный объект типа double инициализируя его x. Однако этот метод вызывает предупреждения при сужающем преобразовании поэтому static_cast все равно предпочтительнее
```


# Псевдонимы типов
```c++
using Distance = double; // Создаём псевдоним Distance для типа double.
Distance x{ 4.5 };  // Теперь везде, где нужно писать double тип можно писать Distance (double тоже можно)
```
## Именование псевдонимов типов
В современном C++ псевдонимы типов желательно называть с большой буквы.

Раньше использовались как суффиксы _t, _type или без суффикса вообще.
## Смешивание типов
Не стоит присваивать переменной с одним псевдонимом значение с другим псевдонимом одного и того же типа. Синтаксически это допустипо и программа скомпилируеться, но семантически нет.
```c++
using Miles = long;
using Distance = long;

Miles x{ 34 };
Distance y{ 45 };

x = y; // Допустимо синтаксически, но семантически не верно
```
## Область действия псевдонимов типов
Псевдонимы типов подчиняються тем же правилам, что и идентификаторы переменных: имеют блочную область видимости если определён внутри блока и глобальную если определён в глобальном пространстве имён:
```c++
namespace Types {
    using RealNumber = double;
}

using LongNumber = long;

int main() {
    int x{ 10 };
    int y{ 4 };
    std::cout << (Types::RealNumber)x / y << std::endl;

    LongNumber z{ 56 };

    return 0;
}
```
## Определения типов
Определения типов это более старый способ создания псевдонима типа.
```c++
typedef long Miles; // Создаём псевдоним Miles для типа long
using Miles = long; // Эквивалентно примеру выше
```
Данный способ лучше не использовать.
## Когда использовать псевдонимы типов
- Для кроссплатформенного кода. Так как к примеру int на разных платформах может иметь разный размер можно использовать конкретный размер:
```c++
#ifdef INT_2_BYTES
using int8_t = char;
using int16_t = int;
using int32_t = long;
#else
using int8_t = char;
using int16_t = short;
using int32_t = int;
#endif
// Примечание: предполагаеться что мы знаем какой размер имеет каждый тип на каждой платформе. Мы просто даём псевдоним, чтобы на другой платформе не заменять int на short
```
- Для упрожения чтения сложных типов. Например:
```c++
using VectPairSI = std::vector<std::pair<std::string, int>>; // Проще использовать одно слово вместо нескольких
```
- Для документирования. Допустим чтобы показать, что именно возвращает функция.
```c++
// Вместо
int gradeTest();

// Написать
using TestScore = int;
TestScrore gradeTest();
```
- Для упрощения сопровождения кода. Чтобы можно было легко поменять к примеру тип возвращаемого значения.
```c++
using UserID = short; // Если мы захотим поменять тип, который используеться для идентификатора пользователя мы можем это сделать только один раз вместо того, чтобы каждый раз изменять к примеру тип переменной, которая хранит идентификатор пользователя.

UserID getUserID();
UserID x{ getUserID()}
```

В любом случае это нужно делать если это явно упрощает читаемость и сопровождение. Нужно находить баланс так как в любом случае псевдоним типа это дополнительный идентификатор.


# Определение типов при помощи ключевого слова auto
При помощи данного способо мы можем не сами выщитывать какого типа будет переменная, а автоматически выщитывать на основе ее инициализаторов
```c++
auto d{ 5.6 }; // Компилятор сам определит, что новая переменная d будет иметь тип double
auto i{ 5 + 4 }; // Будет тип int
auto f{ 6f }; // Будет тип float
auto b{ isTrue() }; // Будет тип bool, если isTrue возвращает bool
```

Данная вещь называеться - **вывод типа**. 

До C++17 при использовании auto с прямой списочной инициализацией ({}) тип мог быть немного другим (std::initializer_list<тип инициализатора>). Многие компиляторы сделали так, что даже в более ранних версиях это убрали и вывод типов выводит тип инициализатора (как в C++17). 
## Необходимо наличие инициализатора
Если отсутствует инициализатор или функция-инициализатор возвращает void, то будет ошибка
```c++
void greet() {
    std::cout << "Hello world!" << std::endl;
}

int main() {
    // Во всех этих случаях будет ошибка
    auto foo;
    auto bar{}; // Даже при списочной инициализации
    auto baz{ greet() };

    return 0;
}
```
## const отбрасываеться из выведенного типа
Хоть const и являеться частью типа, он отпрасываеться после вывода
```c++
const int age{ 90 };
auto x{ age }; // Имеет тип int, а не const int

const auto x{ age }; // Нужно указать const, чтобы новая переменная была константной
```
Тоже самое касаеться и constexpr
## Вывод типов для строк
Для вывода типа для строк потребуеться использовать суффиксы
```c++
#include <iostream>
#include <string>
#include <string_view>

int main() {
    using namespace std::literals;

    auto x{ "Hello world!" }; // Получим тип char*
    auto y{ "Hello world!"s }; // Получим тип std::string
    auto z{ "Hello world!"sv }; // Получим тип std::string_view
    
    return 0;
}
```
## Приимущества и недостатки
### Приимущества
- Предостирегает от того, что можно случайно забыть инициализовать переменную
- Предотврощает непреднамеренные преобразования типов, которые могут влиять на производительность
```c++
std::string_view getString();

std::string s1 { getString() }; // Дорогостоющее преобразование из string_view в string
auto s2 { getString() }; // Нет преобразований
```
### Недостатки
- Мы не видим информацию о типе и соответственно можно допустить больше ошибок

Вывод типов можно использовать там, где тип не имеет особого значения. Например в ситуации с делением (целочисленное или деление с плавающей точкой) тип имеет значение или при смешивании знаковых и беззнаковых чисел тип также имеет значение.


# Вывод типов для функций
```c++
// Компилятор сам определит тип возвращаемого значения
auto summa(int a, int b) {
    return a + b;
}
```
Тип возвращаемого значения должен быть одинаковый, иначе будет ошибка. Код ниже не будет работать
```c++
auto summa(int a, int b) {
    if (true) {
        return a + b;
    } else {
        return static_cast<double>(a + b);
    }
}
```
Если очень необходимо иметь разные типы, то нужно **указать** тип возвращаемого значения, тогда компилятор попытаеться неявно преобразовать тип возвращаемого значения в указанный.
## Синтаксис указания возвращаемого значения в конце функции
```c++
auto имя_функции(параметры) -> тип_возвращаемого_значения {
    тело функции...
}
```
Слово auto всегда необходимо в начале функции, если нужно использовать тип возвращаемого значения в конце. Вот несколько примеров
```c++
auto summa(int a, int b) -> auto {
    return a + b;
}

auto summa(int a, int b) -> int {
    return a + b;
}
```
Синтаксис указания возвращаемого значения в конце функции необходим в несольих случаях
- Упрощение чтения
- Выравнивание объявлений функций в начале строки
- Если тип возвращаемого значения зависит от параметров функции
- Нужен для лямбда-функций
## Вывод типа параметров функции
В C++ нельзя выводить тип параметров функции. Код ниже не будет работать должным образом
```c++
auto summa(auto a, auto b) {
    return a + b;
}
```
Хотя данный код может скомпилироваться, он не занимаеться выводом типа параметров функции. К тому же это работает не во всех версиях языка.
## Приимущества и недостатки вывода типов функции
### Приимущетва
- Можно использовать, если тяжело самому расчитать какой тип будет
```c++
auto add(unsigned short x, char y) {
    return x + y; // Самому тяжело понять тип данного выражения
}
```
- Не нужно переписывать код, если тип возвращаемого значения зависит от реализации языка.
### Недостатки
- Функция должна быть полностью определена до начала использования. Предварительного объявления недостаточно.
- Тяжело отслеживать тип, если среда разработки не указывает его

Лучше явно указывать тип возвращаемого значения за исключением случаев, если тяжело понять какой тип будет у возвращаемого значения, он не важен или ненадёжен (к примеру изменяеться в зависимости от реализации).


# Перегрузка функций
Рассмотрим пример. Нам нужно сложить 2 числа. Напишем для этого функцию
```c++
int add(int a, int b) {
    return a + b;
}
```
Но что если мы хотим складывать числа с плавающей точкой. Конечно, можно сделать новую функцию, а можно перегрузить текущую. Имя функции сделать такое же, но например изменить тип параметров
```c++
// Оригинальная функция
int add(int a, int b) {
    return a + b;
}
// Перегрузка
int add(double a, double b) {
    return a + b;
}
```
Теперь мы можем вызывать эту функцию с разными аргументами. Компилятор сам на основе аргументов определит какую перегрузку мы используем. Это называеться разрешением перегрузки.
```c++
int main() {
    std::cout << add(1, 1) << std::endl;
    std::cout << add(5.5, 5.5) << std::endl;

    return 0;
}
```
## Дифференциация перегруженных функций
Как он понимает, что это именно перегрузка, а не другая функция и допустима ли эта перегрузка
### Перегрузка на основе количества параметров
```c++
void print(int a, int b) {
    std::cout << a << b << std::endl;
}
void print(int a, int b, int c) {
    std::cout << a << b << c << std::endl;
}
```
Этот код рабочий. Компилятор легко поймет какая перегрузка используеться при вызове на основе количества переданных параметров
### Перегрузка на основе типа параметров
```c++
int add(int a, int b) {
    return a + b;
}
int add(double a, double b) {
    return a + b;
}
int add(double a, int b) {
    return a + b;
}

```
Этот код рабочий. Опять же компилятор поймёт какую перегрузку использовать на основе типа переданных аргументов

Для параметров, передаваемых по значению квалификатор const не учитываеться и следующий код выведет ошибку о повторном определении функции
```c++
void print(int a, int b) {
    std::cout << a << b << std::endl;
}
void print(int a, const int b) {
    std::cout << a << b << std::endl;
}
```

Псевдонимы типа не будут считаться отдельным типом.

Параметры с многоточием также считаються уникальным типом параметров
```c++
// Ошибки не будет
void print(int a) {
    // Реализация...
}
void print(int a, ...) {
    // Реализация...
}
```
### На основе количества параметров и их типе
```c++
void print(int a, int b) {
    std::cout << a << b << std::endl;
}
void print(int a, double b, int c) {
    std::cout << a << b << c << std::endl;
}
```
Код рабочий. Опять же компилятор поймёт какую перегрузку использовать на основе типа переданных аргументов
### Нельзя сделать перегрузку на основе типа возвращаемого значения
Код ниже приведёт к ошибке
```c++
void print(int a, int b) {
    std::cout << a << b << std::endl;
}
int print(int a, int b) {
    std::cout << a << b << std::endl;
    return 0;
}
```
Это сделанно намеренно, чтобы исходя из вызова функции можно было легко определить какая перегрузка используеться. В противном случае нужно было бы очень дасканально исследовать все перегрузки.


# Разрешение перегрузки функций
При вызове перегруженной функции компилятор выполняет последовательность действий для определения какая именно перегрузка соответствует данному вызову.
## Последовательность определения перегрузки
1. Компилятор пытаеться найти точное совпадение. Это происходит в два этапа. Сначала компилятор проверяет существует ли перегрузка, тип аргументов которой **точно** совпадает с типом аргументов функции, которую вызывают.
```c++
void print(int a) {
    std::cout << "1 overloading: " << a << std::endl;
}
void print(double a) {
    std::cout << "2 overloading: " << a << std::endl;
}

int main() {
    print(1); // Я передаю int в аргументы. омпилятор видет, что есть перегрузка, оторая принимает точно int и вызовет её.

    return 0;
}
```
Затем компилятор применяет ряд **тривиальных преобразований** к аргументам в вызове функции. Они представляют собой набор конкретных правил преобразования, которые меняют тип, но не меняют внутреннее представление значения. К ним относяться
- Преобразование Ivalue в rvalue
- Преобразование квалификаторов (например, преобразование из неконстантного типа в константный)
- И ряд других...
```c++
void print(const int a) {
    std::cout << "1 overloading: " << a << std::endl;
}
void print(double a) {
    std::cout << "2 overloading: " << a << std::endl;
}

int main() {
    print(1); // Вызоветься первая перегрузка

    return 0;
}

```
2. Если на первом шаге компилятор не смог найти соответствующую перегрузку, на втором шаге компилятор выполняет числовое продвижение аргументов в вызове функции
```c++
void print(int a) {
    std::cout << "1 overloading: " << a << std::endl;
}
void print(double a) {
    std::cout << "2 overloading: " << a << std::endl;
}

int main() {
    print('a'); // char продвегаеться до int. Вызываеться первая перегрузка
    print(5.5f); // float продвигаеться до double. Вызываеться вторая перегрузка

    return 0;
}
```
3. Если соответствующая перегрузка не найдена компилятор выполняет числовове преоразование
```c++
void print(std::string a) {
    std::cout << "1 overloading: " << a << std::endl;
}
void print(double a) {
    std::cout << "2 overloading: " << a << std::endl;
}

int main() {
    print('a'); // char преобразовыветься в double. Вызываеться вторая перегрузка
    print(5.5f); // float преобразовываеться в double. Вызываеться вторая перегрузка

    return 0;
}
```
4.  Если соответствующая перегрузка не найдена компиляор выполняет пользовательские преобразования. Например, классы могут определять преобразования в указанные типы. Если пребразование указанно, компилятор вызовет его неявно и определит есть ли соответствующая перегрузка
```c++
class X {
    public:
        // Пользовательское преобразование для объектов этого класса в int
        // Т.е. это вызоветься, если нужно будет преобразовать объект этого класса в int и значение этого объекта замениться возвращаемым значением
        operator int() {
            return 0;
        }
};

void print(std::string a) {
    std::cout << "1 overloading: " << a << std::endl;
}
void print(int a) {
    std::cout << "2 overloading: " << a << std::endl;
}

int main() {
    X x;

    print(x); // X преобразовыветься в int (в функцию передаёться 0). Вызываеться первая перегрузка

    return 0;
}
```
Далее компилятор может выполнить дополнительные неявные преобразования. Например, если бы наше пользовательское преобразование описывало бы не преоразование в int а преобразование в char, компилятор бы сначало преобразовал x в char (вызвал бы пользовательское преобразование), а затем так как нет перегрузки, которая принимает char продвинул бы его до int
5. Если соответствующая перегрузка не найдена компиляор будет искать перегрузку, использующую многоточие
6. Если соответствующая перегрузка не найдена компиляор выдаст ошибку.
## Неоднозначные совпадения
Может произойти так, что компилятор может увидеть более одного кандидата на соответствующую перегрузку. В таком случае будет ошибка
```c++
void print(int x) {
    std::cout << x << std::endl;
}
void print(double x) {
    std::cout << x << std::endl;
}

int main() {
    print(5L); // Ошибка

    return 0;
}
```
Сначало компилятор не сможет найти точного соответствия. Числовое продвижение также не поможет найти соответствующую перегрузку, так как long не может продвигаться. Значит нужно делать числовое преобразование, но long может преобразоваться как в int так и в double. Следовательно, есть два кандидата на соответствующую перегрузку.

Аргументы по умолчанию также могут приводить к неодназначным совпадениям.
### Устранение неоднозначных совпадений
- Определить новую перегрузку, которая принимает значение, которое приводит к неоднозначному совпадению
- Явно привести аргумент к типу, который не будет вызывать неоднозначного совпадения
- Если передаваемое значение - литерал, использовать суффикс
```c++
foo(0u); // Использовать суффикс u (или другой), если к прмеру передача 0 (int) вызовет неоднозначное совпадение
```

# Запрет использования функций с определённым аргументом
```c++
void print(int x) {
    std::cout << x << std::endl;
}

int main() {
    print(5);
    print('a');

    return 0;
}
```
Данный код будет работать без ошибок. Так как char конвертируеться в int, а что, если я не хочу, чтобы функция могла вызываться с char? Для этого можно использовать запись ниже
```c++
void print(char) = delete; // Теперь такой вызов (print('a')) приведёт к ошибке
```
Такая функция называеться удалённой и являеться перегрузкой. Она участвует в разрешении перегрузки, поэтому код ниже приведёт к ошибке неоднозначного совпадения
```c++
void print(int x) {
    std::cout << x << std::endl;
}
void print(double) = delete;

int main() {
    print(5L); // Неоднозначное совпадение

    return 0;
}
```
Соответственно код ниже также приведёт к ошибке
```c++
void print(double x) {
    std::cout << x << std::endl;
}
void print(int) = delete;

int main() {
    print('a'); // Ошибка так как char продвигаеться до int, а вызов с int запрещён

    return 0;
}
```


# Аргументы по умолчанию
Функции можно указать аргументы по умолчанию.
```c++
void print(int x = 4) {
    std::cout << x << std::endl;
}

int main() {
    print(); // Используеться аргумент по умолчанию
    print(5); // Указываем свой аргумент. Аргумент по умолчанию не используеться

    return 0;
}
```
Если у функции есть аргумент по умолчанию, но мы не указываем свой при вызове (как в первом случае), компилятор сам подставляет аргумент по умолчанию в месте вызова функции на этапе компиляции.
## Несколько аргументов по умолчанию
Функцция может иметь несколько аргументов по умолчанию
```c++
void print(int x = 4, int y = 5) {
    std::cout << x << y << std::endl;
}
```
Если указан аргумент по умолчанию, то все следующие аргументы должны быть также по умолчанию. Код ниже не допустим
```c++
// Ошибка. z должен иметь значение по умолчанию
void print(int x = 4, int y = 5, int z) {
    std::cout << x << y << std::endl;
}
```
Начиная с C++23, можно указать какой именно параметр будет переопределён, а какой будет по умолчанию
```c++
void print(int x = 4, int y = 5) {
    std::cout << x << y << std::endl;
}

int main() {
    print(, 1); // Выведет 41 так как 4 берёться как значение по умолчанию для первого аргумента, а второй параметр переопределяется с 5 на 1
    
    return 0;
}
```
## Где объявлять аргументы по умолчанию
Аргументы по умолчанию нельзя повторно определить в одной и той же единице трансляции и нельзя объявлять после вызова функции. Следующий код вызовет ошибку
```c++
// Предварительное объявление
void print(int x, int y = 4);

// Определение
void print(int x, int y = 4) {
    std::cout << x << y << std::endl;
}

// Ошибка так как аргумент по умолчанию объявлен и в предварительном объявлении и в определении
```
```c++
// Предварительное объявление
void print(int x, int y);

int main() {
    print(1);

    return 0;
}

// Определение
void print(int x, int y = 4) {
    std::cout << x << y << std::endl;
}

// Ошибка так как аргумент по умолчанию объявлен после использования
```
Наилучший вариант указать аргумент по умолчанию в предварительном объявлении
```c++
void print(int x, int y = 4);

int main() {
    print(1);

    return 0;
}

void print(int x, int y) {
    std::cout << x << y << std::endl;
}
```
## Аргументы по умолчанию и перегрузка функции
```c++
void print(int x) {
    std::cout << x << std::endl;
}
void print(char x = 'a') {
    std::cout << x << std::endl;
}

int main() {
    print(); // Будет вызвана перегрузка, там, где аргумент по умолчанию

    return 0;
}
```
Значения по умолчанию могут приводить к неоднозначному совпадению
```c++
void print(int x = 1) {
    std::cout << x << std::endl;
}
void print(char x = 'a') {
    std::cout << x << std::endl;
}

int main() {
    print(); // Неоднозначное совпадение. Обе перегрузки имеют аргумент по умолчанию

    return 0;
}
```
